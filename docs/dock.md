# 程序坞：应用级窗口层

把「收起的弹窗」变成一条跨页面、跨刷新都还在的程序坞条目，点条目按快照重建窗口。
它挂在 `App` 的 Router 内、布局外（`DockProvider`），页面组件不参与恢复。

## 谁能收起

只有**阅读类窗口**接程序坞：`MarkdownPreviewModal`、`RecordDetailModal`、
`ImagePreviewModal`、`VideoPreviewModal`。它们都是「看内容」的窗，收起再打开仍是同一份内容。

确认 / 短表单类弹窗（`ConfirmModal`、删除确认等）不接：关掉即完成决定，没有「先收起来待会儿再点开」的状态。
要接入必须同时提供可序列化快照与恢复渲染器，不能只加一颗按钮。

## 描述符与快照

业务弹窗通过 `FreeModal` 的 `dock` 传一份 `DockDescriptor`：

| 字段 | 契约 |
| --- | --- |
| `id` | **当前内容**的条目 id，稳定且跨页唯一（`kind:页面:内容` 一律由内容派生）：哪颗图标算「正在显示」、header 报哪一格、`⌘M` 登记在谁身上都按它；同一内容重复收起只替换这一条 |
| `surfaceId` | **窗自己那条**条目 id（只有 `origin: 'dock'` 传，等于打开它的图标）：开合 / 滑动 / 收起动画按它找框体、X 删它、收起缩回它，窗内翻篇后不变；不传沿用 `id` |
| `kind` | 四种阅读窗口之一，决定恢复时用哪个渲染器 |
| `title` | 程序坞 tip 与恢复窗口的标题 |
| `snapshot` | 只放可进 localStorage 的字段；恢复不依赖任一页面状态 |
| `origin` | `page` 收起后执行 `onClose` 清页面状态；`dock` 再收起只回坞、不删条目 |
| `id` 已存在 | 收坞按钮换成 `IconMinus` 横线「最小化到程序坞」，行尾 `IconX` 负责关闭并删条目 |
| `disabled` | 当前不可收起（编辑中 / 上层确认开着）：按钮保留但置灰 |

**已收录才回坞**：页面弹窗只有在「程序坞里已有当前内容那条」时，窗口控制图标 / Esc / 遮罩 / 空格
才收回程序坞；未收录的页面弹窗仍走 `onClose` 正常关闭。
**程序坞窗口永远算收录**：它是某颗图标的窗（`surfaceId` 那条），窗内翻篇只是临时换内容，
header 与关闭动作始终是「最小化到程序坞 / 关闭并从程序坞移除」，不随内容变。
header 的「收起到程序坞」按钮仍可主动把未收录的页面弹窗收进去，这一下才有条目。
已收录窗的 header 里，横线「最小化到程序坞」负责回坞、**行尾 `IconX` 负责关闭并删条目**；
X 在所有弹窗里固定在最右，未收录窗的 X 只走普通关闭。Mantine 原生关闭按钮一律不画。
同 id 条目已在程序坞时，从列表打开页面弹窗，程序坞对应图标保持激活（实心运行点）。

快照只放「能重新取到内容的最小定位」，不放内容本身：Markdown 只存标题、相对路径与页面标识，
正文按笔记名从仓库重读（读不到时窗里给占位说明，读失败与「笔记已删」分开说）；记录详情只存
`recordId` 与标题；图片 / 视频只存路径与当前条目，名称、取图地址、视频封面都在渲染时按路径推导
（拼法与文件页预览、网格缩略图同一套）。旧存储里带 `name` / `src` / `poster` 或全文的条目照样能读，
多出来的字段直接忽略。条目最多 8 条，超出按 `createdAt` 淘汰最旧的，避免 localStorage 被快照撑爆。

## 恢复与状态

- 条目里只有 `kind + snapshot`，恢复时按 `kind` 动态 import `src/dock/windows/` 下的渲染器，
  所以切页面、刷新后都能点开，页面路由不参与恢复。
- 恢复窗口与页面弹窗**保持同一套操作**：页面还在时复用页面登记的能力；页面卸载 / 刷新后，
  图片 / 视频窗复用文件页同一套 `useEntryDelete` / `useWallpaper` / `useImageCropSave` /
  `useVideoCapture` / `useOpenExternal`，只把数据源换成快照列表并补一层窗口内确认层；
  Markdown 窗用页面同一个 `useActiveNote` + `useEnglishNotes` 按笔记名恢复正文、翻篇、
  保存、刷新与删除，不再依赖已卸载页面的闭包；记录窗用页面同一个 `useRecordDelete` +
  `useRecordDetailNav` + `useReviewRecords` 按记录 ID 恢复删除与翻页。
  动作函数只有一份，各宿主只换数据源。不会因为换页少一排按钮。
  图片 / 视频的翻篇是窗口自己的状态，再次收起时写回快照。
- 恢复窗口**永远从普通尺寸出来**：页面里记住的阅读 / 网页全屏不继承，收起前也会先退出整屏与
  网页全屏；打开另一扇程序坞窗口前若页面弹窗还占着浏览器整屏，Provider 先退出，避免旧窗继续铺满。
- 页面弹窗收起后立即 `onClose`：宿主页面状态不能留一半，否则下次从页面打开会撞旧状态。

## 层级

全局层级只在 `src/dock/constants.ts` 定义（页内拖拽这类自己层叠上下文里的层级留在各页面）：

| 层 | z-index |
| --- | --- |
| 普通弹窗 | 200 |
| 服务页全屏拖拽 | 700 |
| 换窗时旧窗的克隆层 | 999（垫在新窗口层下） |
| 恢复出来的程序坞窗口 | 1000 |
| 程序坞条与右下角开关 | 1010 |
| 弹窗内就近弹层（视频设置 / 选集、图片列表 / 裁剪） | 1020 |
| 通知 | 1030 |
| 二次确认 | 1040 |
| 收放 / 飞入动画的克隆层 | 1150 |
| Tooltip | 1200 |

程序坞条必须压过所有弹窗遮罩，遮罩才盖不住它；恢复窗口要压过页面里已经开着的弹窗。
**通知必须压过程序坞窗口与程序坞条**，否则程序坞窗口里截图成功这类提示会被窗口盖住；
二次确认仍压过通知，需当场处理的确认不能被提示挡住。

## 视觉与位置

程序坞固定悬浮在**屏幕底部**，不向页面要空间：Header / Navbar / Main 保持铺满，程序坞用 `fixed`
盖在内容上方。**默认收起**，只露出右下角一列固定按钮：最下一颗是 `IconApps` 开关，展开后这一列里
多出的按钮（目前是编辑）**默认整颗收在开关背后**，指针移进这一列或聚焦到隐藏按钮时才沿槽位向上弹出；
编辑模式激活时编辑按钮钉住不收起。点击开关，整条从屏幕下沿滑出，图标变成向下箭头，再点滑回去；
收起时开关上带条目数角标。

- 图标固定 `36px`，hover 按指针沿底部横轴的距离放大，最大 `110%`；位置不动，重叠交给 z-index。
- 盒子是**固定亮色毛玻璃**，不跟主题变深：低 alpha 白色 + `backdrop-filter` 提亮与饱和，
  透出来的就是背后的颜色，hover 只让玻璃稍微更亮。padding `11px 12px`、gap `8px`、圆角 `20px`。
- 程序坞没有可配置项：位置、大小、放大倍率、显隐都固定，不从设置读值。
- 同一类窗口自动排在一起（图片 → 视频 → 文档 → 记录），组与组之间画一条细线；
  程序坞条、header 计数与切换顺序都读同一份排序。
- 图标本体是彩色圆角 app 图标。激活只有一种：**实心运行点**给「窗里正显示的正是这一条」
  （页面里已打开同 id 弹窗时也是实心点）。窗是这颗图标开的、里面却翻到一条**不在程序坞**的
  内容时，这颗图标**不算激活**，只画成一格 hover 态（图标那层 hover 阴影），点它会装回自己的
  内容；翻到的内容本身在程序坞时不做任何标记，因为那时它自己那颗图标已经是实心点。
- 编辑模式点图标直接移除。默认仍显示彩色图标；hover / focus 到某一格时，这一格才浮出一层
  **完全盖住**图标、背景与 1px 边框的深色毛玻璃遮罩（底层图标同时隐去，不叠影），中间是移除图标；
  整格点击都触发移除（遮罩本身不拦指针）。
- 全屏弹窗打开时程序坞条与右下角控件默认收起；若全屏期间又因收进新窗口弹出来，
  程序坞条与图标先降到低透明度让出内容，指针回到条上再平滑恢复。退出全屏后回到**进全屏前的
  展开态**，不会一直收着；右下角按钮组同时恢复。
- 右下角控制按钮常态也带透明度，hover / 激活才实体化；除最下面开关外的按钮默认收成一格叠在它背后，
  hover / 聚焦才弹出，编辑模式钉住；全屏时整组隐藏，也不留看不见的可点区域。
- 文件页图片 / 视频瓦片 hover 时可直接「收起到程序坞」：不打开预览，用 `collect` 把当前目录的
  同类列表与这一条交给程序坞，恢复后仍是完整预览；源元素也是瓦片本体，飞入动画照常。
- 收进新条目时程序坞会**自动展开**，先摆出虚线虚位再接飞入动画；不要求用户先手动点开。
- 展开后右下角按钮组里多一颗编辑按钮：进入编辑模式后点程序坞图标不再打开 / 收起，而是直接移除；
  移除最后一个条目会同时退出编辑模式。

## 一次只开一扇

Provider 只维护一个 `windowSlot`，它自己带 `phase`（`opening` / `closing`）与 `removeOnExit`：

- **点正在显示那条的图标**：当前窗缩回程序坞（`removeOnExit: false`），条目保留；再次点击再展开。
  窗自身的根节点固定（`surfaceId` 就是收坞条目 id，开合动画按它认框体），翻篇后窗与条目都不换。
- **点「窗是我开的、内容却翻走了」那颗图标**（hover 态那一格）：不收起，而是**把这一条的快照
  重新装回这扇窗**（重挂窗口体、窗本身不重建），回到它自己的内容后 hover 态当场消掉。
- **程序坞窗口再收起来只回它自己的图标**：翻篇换来的内容不写回任何条目，下次点它仍装出它自己那份。
- **点另一图标**：不先回坞再出来，直接把 `windowSlot` 换成新窗口，新旧两扇按程序坞顺序
  **左右滑动**（`slide`）；新窗从旧窗边缘内 `56px` 处起步，先压住旧窗再滑到正中，旧的完整滑出。
- **已收录窗口的关闭动作（横线最小化 / Esc / 遮罩 / 空格）**：统一收回到程序坞，条目保留
  （程序坞窗口就是回它自己那颗图标）。行尾 X 不参与这套回坞动作，它是「关闭并从程序坞移除」，
  程序坞窗口的 X 删的是**它自己那条**。未收录的页面弹窗按自身 `onClose` 正常关闭。
  收起阶段复用原组件实例（窗根节点与 React key 都不换）。
- **移除**：header 的 `IconX`「关闭并从程序坞移除」或程序坞编辑模式点条目，才真的删。移除当前展开的那扇时
  `removeOnExit: true`，按弹窗默认淡出走完再删；移除未展开条目直接删，不跑动画。
- 收起动画进行中忽略其它程序坞点击，避免两套状态同时抢窗口。

## 动画

`src/dock/utils/dock-motion.ts` 是程序坞窗口动画的唯一实现处：

- **框体只认挂着内容框的根节点**：关掉的弹窗只卸载内容框，根节点还留在 DOM 里，
  所以 `data-dock-surface` 只在窗开着时挂，查找也只取挂着 `section[role="dialog"]` 的那个
  （多个都挂着时取最后挂进 DOM 的）。拿空壳量框体，开合动画会整段被跳过。
- **第一次打开**：真实框体从图标正中心由小长到大（`growWindowFromDock`，420ms），带一点回弹。
- **最后一次收起**：真实框体由大到小缩到目标图标正中心（`shrinkWindowToDock`，220ms），同时遮罩淡出。
  程序坞若已被手动收起，收坞前先按条目 id 把程序坞无过渡展开并摆出目标虚位，再量最终图标位置；
  落点不再回退到右下角开关，不会出现窗口飞向右下角的假动作。
- **切换窗口**：旧窗先克隆并固定，旧窗整块向左 / 右滑出屏幕（240ms），新窗从旧窗边缘内 `56px`
  处滑入（360ms，`slideWindowIn` / `slideWindowOut`），起步就压住旧窗；旧窗比新窗先离场完，
  不靠淡入淡出。
- **移除当前窗口**：`dismissWindow` 只做 140ms 淡出与轻微缩放，不产生收坞位移。
- **页面弹窗 / 瓦片收进程序坞**（`dock-fly.ts`）：条目先出现成虚线**虚位**，源框体的克隆从原位置
  由大到小飞到虚位中心，落定后图标再由小到大长出来（`data-receiving`）。
- 开窗遮罩从透明长到原样，收窗反过来（`dock-overlay.ts`），不让背景在窗口飞行途中硬切。
- `prefers-reduced-motion: reduce` 时全部跳过，只做即时挂载 / 卸载。

## 计数与快捷键

`⌘M` 收起当前最上层、可收起的弹窗；键位监听在 `layouts/BasicLayout`。`FreeModal` 通过
`useDockMinimize` 在打开时登记进 `modalStack`，`minimizeTop()` 返回是否真的收到一扇。

- 程序坞恢复窗的 header 计数与 `←` / `→` **一律按程序坞条目**（与程序坞条同一份排序）：
  格位优先取「窗里正显示的那一条」，它没收录时退回「这扇窗自己的条目」，所以计数永远是
  程序坞的格子、不会跳回内容翻篇；方括号 `[` / `]` 仍是内容翻篇，视频快进在这扇窗里让位
  （只有一条条目时才让回给媒体）。`⌘←` / `⌘→` 由 `layouts/BasicLayout` 同样按程序坞顺序切。
- **窗内翻篇不产生新条目**：程序坞窗口收起只回它自己的图标，条目快照不动；页面弹窗收起才按
  当前内容写快照 / 新收一条。窗的根节点、React key 与组件实例都不断（点回自己的图标时除外，
  那一下重挂窗口体是为了把内容装回快照）。
- 对已收录的弹窗，**横线最小化 / Esc / 遮罩 / 空格全部收回到程序坞**，条目保留；只有行尾 `IconX`
  「关闭并从程序坞移除」才删。未收录的弹窗行尾 X / Esc / 遮罩走正常关闭；不可收起时这些动作不生效，绝不误关。
  页面弹窗收起后仍执行 `onClose` 清页面状态。

## 存储

收起条目存在 localStorage 的 `app:dock`，里面没有正文，也没有可推导的名称 / 地址（见上节），
所以一条媒体条目只占一组路径，而不是「路径 + 名字 + 一长串 URL」。程序坞没有可配置项：
位置、大小、放大倍率、显隐都是固定形态，所以不再有 `app:dock-settings`。

## 新增一类可收起窗口要动的地方

1. `dock/types.ts` 的 `DockWindowPayload` 加 `kind` 与快照类型（判别联合）；
2. `dock/utils/dock-entries.ts` 的编解码补这一支，坏项一律返回 `null`；
3. `dock/windows/registry.ts` 加动态 import；
4. 新增恢复渲染器：只传快照与 `onRequestClose`，`dockOrigin="dock"`、`dockId={entry.id}`；
   header 操作与页面弹窗逐项对齐（标题、复制路径、内容翻篇、刷新 / 保存 / 删除 / 裁剪 /
   截图 / 外部打开 / 待拖拽 / 全屏），唯一允许的差异是「收起到程序坞」换成「最小化到程序坞」；
5. 业务弹窗接 `dock` 描述符：`id` 稳定、`snapshot` 可序列化、`disabled` 覆盖「不能收」的状态；
6. **动作复用是硬约束**：恢复窗不得在 `src/dock/windows/` 里另写删除、保存、裁剪、截图、
   墙纸、翻篇等业务分支；页面卸载 / 刷新后也必须用页面同一份动作 hook 重新实例化，
   数据源只允许换成快照或按 ID 自取，不能指着已卸载页面的旧闭包；
7. 本文件补契约与已知限制。
