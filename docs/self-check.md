# 改完代码的自检清单

**每次改完代码，提交或交付前必须再走一遍**，不能只保证「能跑」。六条按顺序过：

1. **命令全绿**：`pnpm typecheck` / `pnpm lint` / `pnpm build`。
   （`pnpm lint` = `eslint .` + `scripts/check-structure.mjs` + `pnpm check:md`）
2. **查重复**：有没有同样的文案、格式化、class 拼接、剪贴板逻辑散在多处 → 按
   `shared-utils.md` 上提。
3. **查复杂度**：**禁止 O(n²)**——在循环里 `filter` / `find` 已收集的结果、循环里反复展开数组
   都属于此列。改成单次遍历 + `Map` / `Set` 建索引；昂贵派生值用 `useMemo`，别每次渲染重算。
4. **查注释与实现是否一致**：层级、常量、边界都说对了？过时注释直接改掉，不要留着骗人。
5. **查边界**：空数组、加载失败、空态、越界索引（如 `activeIndex === -1`）是否都有明确处理；
   **错误态不要谎报成空态**（读失败时不能说「还没有数据」）。
6. **查残留**：旧目录、旧引用（`features/…`、已删页面）、失效文档段落是否都清掉了。

## 几条最容易返工的地方

- 前后端字段漂移：改接口就把前端类型、fixture、e2e mock、文档一起改，别只改一边。
- 拆文件时手写样式容易丢声明：拆 `index.scss` 要从原文按块搬，只改选择器名。
- 加 `error` 入参就顺手检查「空态文案是否会与错误态打架」。
- 大改动收尾前跑一遍 `grep` 找遗留的旧路径字符串。

## 前端 / 视觉改动

默认**不做浏览器实测**：不启 dev server、不截图验证，以 `pnpm typecheck` 与 `pnpm lint` 为准；
除非用户明确要求浏览器验证。
