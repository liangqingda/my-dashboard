# 公共化边界：提什么、提到哪一层

`docs/shared-utils.md` 与 `docs/ui-components.md` 各自讲了「逻辑重复第几处要提」「UI 什么时候封
`FreeXxx`」，但都没回答**同一件事同时有 UI 和逻辑时，哪些提、哪些留**。本文件管这件事：
**UI 与逻辑分开判，允许只提一半。**

## 一句话判据

提公共的是**语义相同**的东西，不是**长得像**的东西；两处只是外观相似、语义不同，就只提外观那层，
语义留在调用方。**第二处就该提**是阈值，不是「必须先证明能提」的理由。

## 四种形态

先问两个独立的问题：这段 **UI**（按钮、字段、面板外壳、外观与默认行为）跨页面是否完全一致？
这段 **逻辑**（数据来源、业务语义、持久化、落盘、校验、边界口径）是否也完全一致？四组答案对应四种做法：

| 形态 | UI | 逻辑 | 落点 | 调用方还留什么 |
| --- | --- | --- | --- | --- |
| ① UI 与逻辑都提公共 | 提 | 提 | `src/components/<分类>/<Name>/`（带业务语义就是业务组件） | 只传数据与事件 |
| ② 仅 UI 提公共，逻辑页面定制 | 提 | 留 | `src/components/<分类>/FreeXxx/`（或既有的公共壳） | 传选项、文案、`render` / `children`、`onChange` |
| ③ 仅逻辑提公共，UI 页面定制 | 留 | 提 | 纯函数 `src/utils/<kebab>.ts`；状态机 `hooks/`（要写说明就提升为 `hooks/<hook>/`） | 自己决定怎么画、画在哪 |
| ④ 两者都不提 | 留 | 留 | `src/pages/<Page>/` | 全部 |

各自的现有例子：

| 形态 | 例子 | 为什么这么归 |
| --- | --- | --- |
| ① | `FreeTable`、`FreeModal` 的关窗 / 翻篇 / 全屏键位与框体、`MarkdownPreviewModal` 的正文字号 / 锚点行为 | 两个页面要的是同一套行为，没有页面差异；键位这种「同一时刻只能有一套」的交互必须落在基础壳 |
| ② | `ConfirmModal`（二次确认：说明 + 出口）、`IconPopoverButton`（弹层外壳）、`FilterButton`（筛选按钮）、`FreeSelectField`（字段组）、`FreePanelFooter`（底部说明 + 重置） | 长什么样、怎么开合是同一套；筛什么、说明写什么、点了做什么各页不同 |
| ③ | `@/hooks/useStoredState`、`@/utils/format`、`pages/EnglishNotes/utils/filter-markdown`、`useProseFontScale` | 逻辑能共用，但界面上放哪、长什么样归页面 |
| ④ | `NoteFilter` 的筛选口径（讲解 / 习题 / 错题）、`NotesFilter` 的分类与日期口径、`NoteEditor` 的块编辑 | 语义只属于这一页 |

**②是最容易做错、也最值钱的一档**：它的产出必须是「壳 + 插槽」，不能顺手把某个页面的口径写进壳里
（比如给 `FilterButton` 内置「错题 / 习题」两个筛选项）。壳只认 `active` / `onChange` / `children`
这类中性参数。

## 怎么提

1. **先证语义相同**：把两处的输入、输出、边界条件摆在一起比。口径不同的别合并——英语页面 header 的
   「筛选笔记」（筛列表）与预览弹窗的「筛选正文」（筛正文）只共用按钮外壳，两份面板、两份持久化
   各留各的，这就是正确结果。
2. **按形态选做法**，不要默认「整块复制」或「整块抽 hook」。能只提 UI 就别把语义一起搬进公共件。
3. **落点**：UI → `src/components/<分类>/<PascalCase>/`（某类对象的全站唯一入口用 `Free` 前缀；
   只提供某个动作的现成实现、不构成唯一入口的不挂 `Free`；分类判据见
   `docs/ui-components.md` 的「公共组件按类型分目录」）；纯函数 → `src/utils/<kebab-case>.ts`；
   只有一个页面在用但可分离的状态机 → 该页 `hooks/`；真跨页面才上 `src/hooks/`。
4. **公共件里不许出现页面语义**：代码一旦按某页面的名词、字段、段落标记做判断，说明提过头了
   （注释里举某篇文档当例子不算）。`anchor-blocks.ts` 那句「不认任何文档语义、`<!-- round-index -->`
   一概不看」就是这个边界的样板。
5. **调用方只留「给数据、给事件」**；改完把旧实现直接删掉，不留一份对照。
6. **配置对象也算外观公共资产**：`{ label: { marginBottom: 4 } }` 这类「同一套外观的 params」出现第二处
   就上提成一份常量（`IconPopoverButton/constants.ts` 的 `PANEL_FIELD_STYLES`）。复制的那几份注释里
   往往还写着「同一份口径」——那就是该上提的信号。
7. **页面专属的东西不上提**：文案、业务阈值、存储键、文档语义留在调用方或该页 `constants.ts`；
   存储键按「页面标识（路由）:组件或能力」命名（如 `english-notes:markdown-preview` 与
   `english-knowledge-base:record-detail` 互不掺和），拼法与细则见 `docs/shared-utils.md`
   的「存储键的命名」；同一组件的一组偏好存在同一个对象里，不再一个偏好一把键。

## 常见提错

| 症状 | 实际错在哪 | 改法 |
| --- | --- | --- |
| 共享组件里出现某页面的名词 / 字段判断 | 逻辑提过头 | 语义退回页面，公共件只留插槽 |
| 两处面板各写一遍同款 `Select` + 灰字说明 | 该提 UI 没提 | 提成 `FreeSelectField` 一类字段组件，口径留页面 |
| 同一个「重置」一处手写 `UnstyledButton`、一处用 `Button` | 只提了逻辑没提 UI（或压根没提） | 统一走组件库并封进公共外壳 |
| 公共按钮 / 弹层复用到第二个弹窗，快捷键只在第一处挂、tooltip 也不标键位 | 能力提了，配套交互没跟着提 | 键位 hook 按能力可选挂接：第二处用到哪个按钮就挂哪个键，同一操作在所有弹窗键位与 tooltip 标注一致（如字号 `A` 在主预览与子区块预览都生效） |
| hook 返回 JSX / 带 `className` / 自己包一层布局 | 逻辑里混进 UI | hook 只返回状态与处理函数，渲染归页面 |
| 页面为「统一」再复制一份样式或常量 | 把「提公共」做成了复制 | 上提到 `src/components` 或公共常量 |
| 只有一处用、且不构成某类对象的唯一形态，却先封 `FreeXxx` | 提前封装 | 直接吃组件库；等它真是该类对象的唯一入口时再提 |

## 自检

```bash
# 1. 公共层里有没有页面语义词（注释举例不算，命中后逐条看代码是否真按它分支）
grep -rn "错题\|习题\|笔记" --include="*.tsx" --include="*.ts" src/components
# 2. 有没有同一套外观的 params 被复制（应当只剩公共那份）
grep -rn "marginBottom: 4\|FIELD_STYLES" src
# 3. 同一段字段组合是否在两处各拼一遍
grep -rn "comboboxProps" src
```

命中后用上表判一遍：该提 UI 的封 `FreeXxx`，该提逻辑的收进 `utils` / `hooks`，两者都不同的留在页面。
提完把规格写进组件自己目录的 `README.md`，只有跨文件的判据才回到本文件。
