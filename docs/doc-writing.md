# 规范文档怎么写：本项目落点

通用写法（规则句删掉例子仍成立、三种合法写法、四条检查、文档跟代码走还是进 `docs/`）见
`best-docs` skill。本文件只写本项目的位置与校验，不重复判据。

## 本项目落位

- **跨文件的约定与流程** → `docs/`；一个文件只讲一个主题，新增文件必须同时加进 `AGENTS.md` 的索引表。
- **单个组件 / hook / 页面自己的规格** → 它自己目录的 `README.md`，随代码一起改、一起删。
- **入口 `AGENTS.md`** 只放必须照做的硬约束与索引；细则进 `docs/`，入口行数由 `check-structure` 校验。
- **`CLAUDE.md` 只能是指向 `AGENTS.md` 的软链**，不写第二份内容；结构检查比对，漂移即失败。
- 公共组件目录缺 `README.md` 由 `scripts/check-structure.mjs` 拦；新增组件时必须一起写。

## 改完检查

1. 入口索引是否覆盖「新建」场景，不只写「动 X」；
2. 组件 / hook 规格是否留在 `docs/` 里重复了一遍；
3. 清单 / 快照有没有写明来源（脚本 / 目录 / 单一数据源）；
4. `pnpm lint` 的 `check:md` 与入口行数检查是否通过。
