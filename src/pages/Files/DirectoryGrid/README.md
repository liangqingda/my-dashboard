# DirectoryGrid

目录**网格视图**：子文件夹在前、应用其次、文件在后，列宽按内容区宽度铺满。

## 职责边界

- 只负责网格排布与瓦片拼装；取数、筛选、分组折叠、拖拽会话、待拖拽区状态都在页面 / hook 层。
- 分组模式按「文件夹 → 应用 → 文件分类」切成纵向分段，每段一条分组标题，点标题整行展开 / 收起（带高度过渡）；平铺模式不切段。
- 多选（待拖拽区）在容器捕获阶段统一接住：带 `⌘` / `Shift`，或待拖拽区已非空时，点条目变成加入 / 移除，并拦住瓦片原本的打开行为。

## 数据与事件口径

- 入参三类条目已排好序：`folders` / `apps` / `files`；`rows` 是表格视图的事，这里不收。
- 可预览文件按分类分流：视频 → `onOpenVideo`，图片 → `onOpenImage`，外部播放器 → `onOpenExternalVideo`；其它文件点不动。
- 落点分两套：`onDropFolder` 松手放进文件夹；`onDropBlank` 落在空白处（直接拖模式＝搬进当前这一层，不传则落空即取消）。
- 分组折叠：`collapsedGroups` 是已收起的分组键集合，`onToggleGroup` 切换某一组。

## 尺寸口径

- 列数由容器宽度算出（`hooks/useGridColumns`）：`(容器宽 + 列间距) / (瓦片宽度 + 列间距)` 取整，再用 `1fr` 均分——**整行铺满，右侧不留空带**。
- 实际列宽落在 `[瓦片宽度, 瓦片宽度 + 列间距)` 之间：设置面板的「瓦片宽度」（120–360，默认 168）决定的是列宽基准，不是每一格的确切宽度；列数不变时列宽也不变，跨过阈值才加 / 减一列。
- 首帧还没量到宽度、或应用目录定宽列时，回落 `repeat(auto-fill, var(--tile-width))` 按设定宽度折列，避免先闪一屏单列。
- 列间距 `TILE_GRID_GAP`（12px）同时进样式变量 `--tile-gap` 与列数计算，两处必须同源，不能只改一边。
- 变量与列数模板挂在网格根容器上，分组模式下内层每段网格靠继承拿到同一份；量宽度只认宽，不看高——分组收起 / 展开时高度每帧在变，不能带着整网格重渲染。
- 首屏骨架（`FilesStates`）只按设定宽度折列、不跟随铺满，只负责形状。
- 应用目录（`/Applications` 这类）走定宽列 132px，不受这个设置影响：那里的文件夹与应用要同尺寸、不随屏幕拉伸。
- 行高没有下限，由内容撑出（图源盒宽 = 列宽、比例 16:10，加名称与副文案；名称最多两行）。

## 坑

- 条目数量整份在客户端，不做分页 / 虚拟滚动（见 `docs/pages.md`）；别在这里加分页。
- 传给瓦片的回调若每次渲染新建，瓦片 `memo` 会被击穿；hook 层返回值用 `useCallback`，派生数组用 `useMemo`。
