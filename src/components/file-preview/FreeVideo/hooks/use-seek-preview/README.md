# 进度条悬停预览时序（`useSeekPreview`）

管进度条上方那块预览浮层「什么时候浮出、什么时候换帧、帧跟上哪一秒」；
抽帧本身在 [`../use-video-frames/README.md`](../use-video-frames/README.md)，
这里只排时序与记状态。只在 `VideoControls` 内使用，播放器之外不需要知道它。

## 两道门槛

| 项 | 值 | 说明 |
| --- | --- | --- |
| 浮出门槛 | 300ms | 在**同一处**停住才浮出。从画面往下移到底部按钮会路过进度条，划过而不是停住的什么都不出现，所以不会闪一下 |
| 换帧门槛 | 150ms | 停稳才抽当前位置的帧。比浮出早 150ms 发请求，浮出时通常已经是画面，而不是浮出后先转圈 |
| 手抖容差 | 3px | 停着不动的鼠标也会送 ±1px 的 `pointermove`；算成移动的话两档计时被一直重排，浮层与帧都出不来 |
| 同处阈值 | 0.6s | 与上一次真正发请求的时间差小于它就不重抽（2px 的抖动不该反复 seek）。基准只在真发请求时更新，否则慢慢挪动的偏差会累积进基准、永远跨不过阈值 |

## 状态与作废

- `preview` 是浮层落点（`null` 表示不显示），`frame` 是浮层里正显示的那一帧；
- 帧自带 `time`：帧只在停稳后换，可能落后于时间标签，所以给调用方的
  `onPreviewFrameChange` 是「看到的这一帧」——截图不会存错秒；
- 帧回来之前**保留上一张**，不先转圈：一路扫过去时反复「转圈 → 出图」才是那个闪；
- `leave` / `down` 走同一套收尾：清两档计时、`requestTokenRef` 加一作废在途回调、清落点。
  号码作废是为了收起后再 hover 时旧图不会先闪一下；
- 探针还没拿到元数据（`previewReady` 为 false）时不浮出：浮层出不来图，进度条继续用数字浮标，
  不叠两套浮层。

## 和组件怎么分

`VideoControls` 只做事件侧判断（没有 hover 的触屏、按着键的拖动、时长还没解出来）并把指针位置
摊成落点（`seekPreviewAt`）；计时器、落点、帧的时间全在这里，组件不挂 `setTimeout`。
