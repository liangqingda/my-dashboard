# ConfirmModal

二次确认的通用业务组件，外壳基于 `FreeModal` 的 `height="auto"` 那一档。
它不是 `FreeXxx`：名字回答「干什么」（确认），锁的也不是一份外观基线，而是一套确认流程。

## 它锁了什么

- 正文排班：说明块（软底 + 细边）→ 可选额外内容 → 一条细线 → 靠右「取消 / 确认」；
- 两个出口语义：取消永远只是关窗（`onCancel`），确认交给调用方（`onConfirm`）；
- 进行中锁窗：`loading` 时确认按钮 loading、取消按钮 disabled、关闭按钮与 Esc 都失效
  （`onCancel` 不会被调），避免「请求发出去了窗还能关」造成状态对不上。

## 它不管什么

对象是谁、后果说成什么话、额外内容长什么样、什么时候真正发请求。
文案一律由调用方给，组件不猜「删什么」——所以同一个壳能用在文档删除、记录删除，
将来也能用在覆盖、重置这类操作。

## props

| prop | 说明 |
| --- | --- |
| `opened` / `onCancel` / `onConfirm` | 开关与两个出口 |
| `title` | 一句动作说明（单行，如「删除这个文档？」） |
| `description` | 后果说明，放在软底块里；可以传节点（多行、强调某段、等宽路径） |
| `children` | 说明与按钮之间的额外内容（勾选项等），不传就不占位 |
| `confirmLabel` / `cancelLabel` | 默认「确定」「取消」 |
| `danger` | 确认按钮走危险色（删除这类不可逆操作） |
| `loading` / `confirmDisabled` | 请求进行中 / 条件未满足（如一项都没勾） |
| `size` | 宽度档位，默认 `420` |
| `trapFocus` | 是否锁焦点，默认跟随外壳；自带输入框、需要挂载后聚焦表单控件的弹窗可传 `false` |

## 现有用法

- `MarkdownPreviewModal/DeleteConfirm`：标题说动作，说明块第一行是文档路径（等宽），
  额外内容是「这次删什么」的勾选项；
- `Review/DeleteRecordConfirm`：说明两段——问句 + 一句边界（只删记录、笔记文件不动）。
