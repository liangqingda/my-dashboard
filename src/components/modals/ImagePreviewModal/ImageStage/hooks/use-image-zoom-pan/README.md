# use-image-zoom-pan

`ImageStage` 的放大 / 缩小与拖拽移动：捏合、Ctrl+滚轮、指针拖拽最终都落到同一份「倍率 + 位移」。

## 输入通道

| 手势 | 浏览器报什么 | 这里怎么接 |
| --- | --- | --- |
| 触控板捏合（Chromium / Firefox） | 带 `ctrlKey` 的 `wheel` | 原生 `wheel` 监听、`passive: false`；不带 `ctrlKey` 的滚动一律放过 |
| 触控板捏合（Safari） | `gesturestart` / `gesturechange` | 同一份原生监听，按手势起点倍率 × `event.scale` 算 |
| Ctrl + 滚轮 | 带 `ctrlKey` 的 `wheel` | 与捏合同一条路径 |
| 指针拖拽（含 macOS「三指拖拽」、触屏单指） | `pointerdown` / `pointermove` / `pointerup` | Pointer Events + 指针捕获 |

两条原生监听都必须 `preventDefault`：不拦的话浏览器放大的是**整页**，画面本身不动。

## 锁了什么

- **倍率 1–5**：1 就停，不缩到「整图装下」以下（再小只是画面缩在中间一圈黑边里）；
- **锚点缩放**：以指针位置为锚点，锚点下的像素缩放前后停在原地，手指在哪捏就从哪展开；
- **位移夹取**：位移上限 = `(图片未缩放布局尺寸 × 倍率 − 舞台尺寸) / 2`，所以放大时拖不出黑边，
  缩回 1 倍时自动回正（1 倍时上限为 0）；
- **拖拽阈值** `DRAG_CLICK_SLOP`：没过阈值仍算「点了一下画面」（外层据此开合 header）；
- **拖完的 click 要吞掉**：捕获阶段 `stopPropagation`，否则一次拖拽松手会顺带把 header 开合一次；
- **没放大不开始拖**：1 倍时位移上限本来就是 0，按下直接让给单击 / 双击；
- 加载中、读不出来时 `enabled: false`：捏合照样拦掉整页缩放，只是不改倍率；按下也不接拖，
  免得缩放一块空舞台。

## 为什么状态放这里

`ImageStage` 由弹窗用 `key={activeId}` 换实例，换图即重置倍率；状态若提到弹窗里，就得多写一个
「换图要复位」的 effect，还要把 transform 逐层传下去。

## 三指拖拽的前提

macOS 的「三指拖拽」是系统辅助功能（系统设置 → 辅助功能 → 指针控制 → 三指拖拽）：打开后系统
把三指滑动翻译成普通鼠标拖拽，这里靠 Pointer Events 直接兼容。浏览器拿不到触控板的原始触点数，
**没开这个设置时三指滑动不产生任何事件**，组件侧没有可补救的余地。
