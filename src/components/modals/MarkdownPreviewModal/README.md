# Markdown 预览弹窗（`MarkdownPreviewModal`）

组件规格，跟代码放在一起（非全局性文档不进 `docs/`）。**什么时候必须用它（选型）**归
`docs/ui-components.md` 的「场景 → 用哪个」，本文件只讲它的行为契约与实现约束。

渲染栈固定为 `react-markdown` + `remark-gfm` + `rehype-raw`（需要 GFM 表格与 `<details>` 折叠块）；
新增 Markdown 能力时改这个组件，不要在别处另装渲染器。

职责边界：**调用方**决定「相邻文档是谁」「保存落到哪里」以及「这类文档怎么编辑」（编辑插槽见
`docs/markdown-editing.md`）；**导航与编辑态流程**由组件负责。

## props 契约

| prop | 类型 | 说明 |
| --- | --- | --- |
| `opened` | `boolean` | 是否打开 |
| `title` | `string` | 标题，通常传文件名 |
| `markdown` | `string` | Markdown 原文 |
| `loading` | `boolean`（可选） | 正文是否还在取。为 `true` 时正文区只显示居中加载指示、不渲染 Markdown，标题目录为空且不可点，刷新与编辑入口一并收起（没有正文可编辑，也不该把空串写成一篇空文档）。打开 / 翻篇 / 刷新过程中由调用方传 |
| `position` | `{ index: number; total: number }`（可选） | 展示「第几 / 共几」 |
| `relativePath` | `string`（可选） | 文档的相对路径（相对其记录仓库根目录）；提供后 header 出现复制图标按钮，不传则不显示。组件不拼路径，由调用方给 |
| `onClose` | `() => void` | 关闭 |
| `onPrevious` | `(() => void) \| null`（可选） | 上一篇；`null` 表示到头，按钮置灰 |
| `onNext` | `(() => void) \| null`（可选） | 下一篇；`null` 表示到头，按钮置灰 |
| `onRefresh` | `(() => Promise<void> \| void) \| null`（可选） | header 右侧操作组里的刷新按钮；调用方重取最新正文并回灌 `markdown`，返回 Promise 时按钮显示 loading，不传则不显示；编辑中不渲染（刷新会把草稿盖掉） |
| `onSave` | `(markdown: string) => Promise<{ notice?: string }>`（可选） | 提供后才出现「编辑」；落盘由调用方实现，抛错则显示为保存失败，返回的 `notice` 追加在「已保存」提示后 |
| `Editor` | `ComponentType<MarkdownEditorProps>`（可选） | 这一类文档的定制编辑器；不传则点「编辑」只给定制提示 |
| `filter` | `MarkdownPreviewFilter`（可选） | 预览态的内容筛选槽：传了才出现 header 的筛选图标按钮与就近弹层；筛什么、怎么持久化由调用方给。编辑态与保存始终用未筛选的原文 |
| `remove` | `{ description: string \| ((checkedKeys: readonly string[]) => string); choices?: readonly MarkdownPreviewRemoveChoice[]; confirm: (checkedKeys: readonly string[]) => Promise<void> }`（可选） | 提供后才出现 header 的删除图标按钮：点一下或按 `Delete` / `Backspace` 先弹二次确认（`DeleteConfirm`），确认后调用 `confirm`，参数是确认层说明块下方勾中的 key 数组（没传 `choices` 时为空数组）。删什么、删完怎么关弹窗与刷新列表都由调用方决定，组件只给「先问一遍」这一层与那组可选勾选项 |

## 行为细节

### 文档排版

标题、表格、引用、代码块、`<details>` 折叠讲解等都由组件负责，调用方只给原文。

**`**加粗**` 不出字重**：正文里所有 `strong` 一律 `font-weight: 400`，颜色走 `--app-ink-strong`
（普通正文是 `--app-ink-soft`，标题是 `--app-ink`），强调靠墨色深浅区分而不是粗细。
`--app-ink-strong` **夹在正文与标题之间**：浅色下比标题浅一档、暗色下比标题暗一档，与标题始终留
1.3–1.5 倍亮度差；跟着标题往同一边推（浅色更黑 / 暗色更亮）会让加粗看起来像小标题，不要那样改。

**表格外框**：GFM 表格整体描一条 `--app-line` 外框、圆角 8px，行与行之间仍是 1px 单线（表头行靠
`th` 的下边框、其余靠 `td`）。因此 `border-collapse` 必须是 `separate` + `border-spacing: 0`——
`collapse` 下合并边框不参与圆角，外观会变成「外框直角、内线合并」的半成品；末行左右两个角还要单独给
`border-radius`，否则末行 hover 底色会戳出外框的圆弧。子区域预览复用同一份 `.prose`，改一处两处都变。

### 筛选（内容由调用方定义）

header 文档操作组里的筛选图标按钮（排在复制路径之后、刷新之前；编辑态随整组收掉），
点一下在图标下方就近弹出面板（`src/components/buttons/FilterButton`：`bottom-end`、宽 272、带箭头；
英语页 header 的「筛选笔记」用的是同一个按钮组件）。
**弹窗不知道「错题」「习题」这类文档语义**：

- 面板内容、筛选口径、条件持久化都归调用方（`filter.render` / `filter.apply`），组件只管按钮与弹层开合；
- `apply` 只在**预览态**生效：编辑态（含草稿预览）不筛，编辑器与保存拿到的永远是未筛选的原文，
  避免把筛过的正文写回文件；标题目录按筛选后的正文重算，目录与屏上内容始终一致；
- 调用方还可传 `keyword`：预览态在正文里把命中片段包成 `mark` 高亮（不区分大小写，代码围栏内不拆），
  同样只作用于读，编辑态与保存不沾；关键词为空不打标；
- 命中导航由弹窗持有：`render` 收到的 `navigation` 带当前下标、总数与 `next` / `prev`，面板输入框挂
  Enter 下一个、Shift+Enter 上一个，弹窗把目标标记滚到正文居中；当前命中主色实底 + 对比字色，
  其余命中浅一档底色；无命中 / 非预览态时 `navigation` 为 `null`；
- `filter.active` 为真时图标换成主色、tooltip 改口；筛空时正文区显示「没有符合当前筛选条件的内容」，
  而不是一片空白；
- 换篇 / 刷新 / 进编辑 / 关弹窗都会收起面板；面板开着时 Esc 只收面板，不连弹窗一起关
  （`closeOnEscape` 由弹窗的 `panel` 状态把关）。与「正文字号」「文档内交互方式」弹层互斥，同一时刻只开一块；

### 文档内交互（同文档链接 / 折叠块）

header 文档操作组里的「文档内交互方式」图标按钮（`InteractionControl`，图标 `IconHandClick`，
排在正文字号之后、刷新之前；编辑态随整组收掉）管三件「点一下之后会发生什么」的设置，
三件都是**跨篇、跨会话记住的阅读偏好**（`localStorage`，键见 `constants.ts`；括号里是默认值）：

| 分组 | 设置项 | 取值 | 存储键（默认） |
| --- | --- | --- | --- |
| 同文档链接 | 点了链接之后怎么办 | `jump` 滚过去 / `modal` 弹窗打开那一块 | `ANCHOR_LINK_STORAGE_KEY`（`jump`，等于浏览器原行为） |
| 同文档链接 | 子区域预览里能前后切到哪些链接 | `all` 全文所有链接 / `section` 只同一处目录里的那几个 | `ANCHOR_NAV_SCOPE_STORAGE_KEY`（`all`，等于旧行为） |
| 折叠块 | 点了标题之后怎么办 | `expand` 原地展开 / `modal` 弹窗预览 | `DETAILS_BLOCK_STORAGE_KEY`（`expand`，等于旧行为） |
| 折叠块 | 折叠块预览里能前后切到哪些块 | `all` 全文所有 `<details>` / `kind` 全文标题相同的 / `section` 只同一小节里的 | `DETAILS_NAV_SCOPE_STORAGE_KEY`（`section`，范围最可控） |

**弹层按主题分两组**：这个弹层早先只管锚点链接，现在还要管折叠块，所以按钮的 label / tooltip
一并从「同文档链接打开方式」改成「文档内交互方式」；文档里两类内容都有弹窗预览时 hint 补一句
「（有弹窗预览）」、图标换主色（与「筛选生效」同一个表达）。

**分组头与字段标题必须分两档**（`InteractionControl/index.scss`）：分组头是「2px 主色竖标 +
11px 淡色小标签（字距 0.06em）+ 右侧一条横线」，字段标题仍用组件库默认字号与正文墨色。
两者同字号同字重时（早先就是），读起来像并列的四个字段而不是「两组各两项」；横线同时替掉了
两条分组之间的 `Divider`，两组靠 16px 间距 + 各自的分组头分开。组名只写「同文档链接」/「折叠块」，
折叠块那句例子（场景对话原文、故事原文这类折叠块）挂在分组头**下面一行**，不挤在标题与横线之间。

**字段外观与筛选面板统一**：字段标题在上、下拉在下、选中档位的口径用一行灰字补在下面；
`size="xs"`、标题下留 4px、宽 272（与筛选弹层同宽），弹层开着时切换档位不收起，点图标或点外面才关。
这套字段外观（含「下拉不进门户」那条规矩：门户里的列表在 popover 眼里算「外面」，点选项会先把弹层关掉）
统一由 `src/components/fields/FreeSelectField` 给，本组件只提供分组、选项与说明文案，不再自己拼
`Select` + 字段间距常量。

**按钮出现条件**：文档里真有同文档锚点链接（`hasAnchorLinks`）**或**折叠块（`hasDetailBlocks`）时才出现，
且非 `loading`；没有哪一组内容时那一组整组不渲染（只剩一组时不画 `Divider`），两组都没有时按钮也不出现——
没有可点的东西，这档设置也就无从验证。

#### 同文档链接（`[文字](#锚点)`）

**点了链接之后怎么办**：

| 行为 | 点了同文档链接 |
| --- | --- |
| `jump`（默认） | 在当前正文里滚到锚点位置，目录高亮跟着走 |
| `modal` | 把锚点指向的那一节单独开窗（子区域预览），主弹窗留在原处 |

**子区域预览里能前后切到哪些链接**（只影响 `modal` 行为下的前后切换与计数）：

| 口径 | 能切到的区块 | 计数 |
| --- | --- | --- |
| `all`（默认） | 全文所有被链接指向的区块，按链接出现的顺序 | 全文区块数 |
| `section` | 只与当前块**同一处目录**里的链接指向的区块 | 这一处的链接数 |

分组的凭据是区块的 `linkGroup`：指向这一块的**第一条链接**所在的上级标题行号（`-1` 表示在第一个
标题之前），同一处目录里的链接同值。例：`## 讲解` 里列了两轮复习的链接，选 `section` 时计数只有 2，
只能在这两个里切换（测试文档 `learning-record-notes/phrases-a-price-to-pay.md`：讲解 → 两块「本轮习题」、
练习 → 两块「练习…」，各 2 块）；找不到当前块的 `linkGroup` 时退回全文，不让计数变成 0。

- 拦截方式是在 `<article>` 上挂 `onClick`、用 `event.target.closest('a')` 判定，**不用
  `components={{ a: … }}` 换掉 `a` 渲染器**——那会改掉 `react-markdown` 的组件对象，正文的 `useMemo`
  失去稳定性，长文档每渲染一次就重解析一遍。外链与相对路径一律放行（交给浏览器）；
  同文档锚点必须 `preventDefault()`，否则点一下会把地址栏改成 `#…`；
- 区块的切分口径（`utils/anchor-blocks.ts`，纯文本行扫描、跳代码围栏）：
  - 收集 h1–h4 标题行与 `<a id|name>` 定义行，以及 `](#x)` / `<a href="#x">` 指向的目标集合；
  - 锚点归到「它前面最后一个标题」这一节；一节到**下一个同级或更高级标题之前**为止，没有则到文末——
    所以跳到 h2 得到整节（含 h3），跳到 h3 只得到那一小节；
  - **结果按链接出现的先后装配**（`targets` 的插入顺序，不按标题在正文里的位置、也不调用 `sort`）：
    笔记的目录区（`<!-- round-index -->` 那串 `[2026-11-15 12:05 · 复习](#锚点)`，链接文本就是区块标题原文）本来就按「轮次倒序 / 分类」排，
    前后切换要跟着目录读到的顺序走，才算「上一个 / 下一个链接指向的区块」；
  - 每个标题只认第一个落在它这一节里的锚点；一块还带 `parentTitle`（往上找第一个层级更小的标题，
    如 h2 的上级 h1 `2026-11-15 12:05 · 复习`），用来在 header 上交代「这一块是哪一轮的」；
  - 第一个标题之前的锚点单独成一块（`level: 0`、无标题），标题显示锚点本身；
  - 取的是**未筛选**的正文：锚点靠 id 找回，筛选裁掉目录行也仍能定位那一节，与顺序无关；
- 弹窗模式下没认出区块（锚点没有对应标题）时**退回跳转**，不让点击白按一下。

#### 折叠块（`<details>`）

笔记里的「场景对话原文 1」「故事原文」都是 `<details>` + `<summary>标题</summary>` + 正文
（来自 `learn-english` 的 `learning-record-notes/**`），渲染栈给的是浏览器默认行为——默认收着、点标题原地展开。
「文档内交互方式」弹层里的「点标题之后」把它改成可配置：

| 行为 | 点了折叠块标题 |
| --- | --- |
| `expand`（默认） | 什么都不拦，交给浏览器原地展开（等于旧行为） |
| `modal` | `preventDefault()` 后把这一段正文单独开窗（`SectionPreview`），正文里的折叠块保持收着 |

- 解析口径（`utils/details-blocks.ts`，纯文本行扫描、跳代码围栏）：只取**最外层** `<details>`
  （嵌套的留给内层自己展开）；`<summary>` 只认块内第一行非空内容那一行，正文从它之后开始，
  标题去掉行内标记；没有 summary 时标题退化为 `折叠块 N`；`key` 为 `details-<下标>`；
- **必须按「屏上真正渲染的正文」解析**：点击时是靠 DOM 里「这是第几个最外层 `<details>`」回查到下标的
  （`utils/prose-navigation.ts` 的 `getClickedSummary` / `findDetailBlockIndex`），若拿未筛选原文去数，
  筛选裁掉几块之后下标就会错位。所以弹窗里这条链路吃的是 `visibleMarkdown`
  （`filter && !editing.editing ? filter.apply(renderedMarkdown) : renderedMarkdown`），
  与 `PreviewWorkspace` 的口径一致——锚点区块那条仍按未筛选正文算，两份不要合并；
- 点在已展开的正文上不算点标题，只有 `summary` 归这一层；认不出对应折叠块（正文与解析结果漂了）
  时同样退回原地展开，不让点击白按一下；`expand` 行为下永远返回 false；
- **折叠块预览的前后切换范围同样可配**（`listDetailBlockPeers(blocks, index, scope)`），三档：
  - `section`（默认）：只留**同一个标题小节**下的折叠块，计数变成这一小节的块数。分组凭据是每块的
    `groupLine`——「它上面最近的那个 h1–h4」的行号（`-1` 表示在第一个标题之前）；折叠块**内部**
    出现的标题不算，块里的小标题不会把分组拆开。例：`## 看一套…场景对话` 下两个「场景对话原文」
    计数是 `1 / 2`、`2 / 2`，不会切到「故事原文」；`## …小故事` 下的「故事原文」自成一节，计数 `1 / 1`；
  - `kind`：只留**标题相同**的折叠块（去掉末尾序号再比，`titleKey`），不按位置分组。
    例：各轮里的「知识点讲解」互相能切到、「错题讲解 1 / 2 / 3」算一类；读「场景对话原文 1」时
    只在自己的 `1 / 2` 里切，练习题讲解不会插进来；
  - `all`：全文所有 `<details>` 按正文顺序，前后就是相邻的那一块（会跨「原文类」与「练习题讲解类」，
    所以要显式选它，不再是默认）；
  - 三档放在同一个分组里（「点标题之后」「折叠块预览切换范围」），下拉里每一档都有一行口径说明，
    选 `all` 时说明会点明「含练习题的「知识点讲解」」，避免再被误读成「只算原文类」；
  - 分组算法与链接那份共用 `utils/scope-peers.ts` 的 `listScopePeers`（只比分组键，键可以是行号
    或标题），「一处目录 / 一个标题 / 同类标题」这种文档语义仍归各自的解析器
    （`linkGroup` / `groupLine` / `titleKey`）；`kind` 与 `section` 都走「同组」，只有 `all` 不分组；
- **子预览里不再开第三层**：`SectionPreview` 正文里还有折叠块时按浏览器默认展开，不挂点击拦截，
  也不响应 header 上的这档设置（设置只管主预览正文）；
- 正文点击路由只有一处：先问折叠块这一层，接管了就收起链接区块那一层并 return；否则再按链接处理。
  两层子预览互斥（开链接区块前会先收起折叠块预览）。

### 子区域预览（`SectionPreview`）

`modal` 行为下的那一层弹窗是 `SectionPreview`，**两个入口共用**：同文档链接指向的一节、折叠块里的正文。
它不再自己算「哪些段是一组」——`sections`（全部可读段）、`index`、`peers`（能前后切到的下标）都由调用方给
（链接按 `all` / `section` 口径分组、折叠块按全文顺序分组，都是文档语义），标题里的计数就是 `peers` 里的位置。
界面交给 `@/components/modals/FreeModal` 组装（和主预览、记录详情同一套外壳，不再自己拼 `Modal` 与 header 行）：

| 位置 | 内容 |
| --- | --- |
| header 左侧 | 前一段 / 后一段图标按钮、计数（`第 3 / 4 块`）、当前段的标题（`nav` 插槽） |
| header 标题 | 段标题 + 所处的那一节（`parentTitle`），` · ` 连接：`本轮习题 · 2026-11-15 12:05 · 复习`；没有上级标题时只显示段标题（锚点区块顶到锚点本身，折叠块就是 summary 原文） |
| header 右侧 | 正文字号（`headerActions`，`A` 开合面板）、全屏（外壳的 `fullscreen`，`F`）、关闭（`aria-label="关闭区块预览"`） |
| 左侧 | 这一块自己的标题目录（复用 `OutlineNav`，标题少于两条时按它的规则不显示） |
| 正文 | 这一段的 Markdown 源文本（锚点区块**不含本节标题行**，标题已经在 header 上；折叠块是 summary 之后的正文），含它下属的更深层级 |

- **前后切换由 `peers` 决定、不区分层级**：链接那一份按文档里链接出现的先后（顺序来自 `targets`），
  h2 与 h3 相邻时直接跳过去，目录倒序排时切换也跟着倒序；折叠块那一份按「全文 / 同一小节」口径算；
- **首尾贯穿**：最后一块的「下一个」回到第一块、第一块的「上一个」跳到最末一块，
  所以两侧按钮不因「到头」置灰（只有这一档里只算得出一块时才没有下一处可去，两侧都不可点）；
  计数仍是 `第几 / 共几`，回绕时数字直接跳到另一端；
- **快捷键与 header 上那两个按钮同一套键位**：`]` / `】` / `→` 下一块，`[` / `【` / `←` 上一块
  （键位与监听统一在 `FreeModal/hooks/useModalShortcuts`，由子预览自己那份 `nav` 接管；子预览开着时
  主预览的 `shortcutsEnabled` 为 `false`，两组键不会打架）。按键只切块、不把焦点挪到按钮上（焦点环全站关闭，见「导航」一节）；
  键位与按钮一样贯穿（末尾 `]` 回到第一块）；只有一块可切时按键不动作；
  正在输入时不抢字符（`@/utils/typing-target`）；
- **按钮文案由调用方给**（`previousLabel` / `nextLabel`，缺省「上一个区块 / 下一个区块」）：
  链接那一层是「上一个链接区块 / 下一个链接区块」，折叠块那层是「上一个折叠块 / 下一个折叠块」——
  两层共用同一个组件，用户得知道自己现在切的是哪一种；
- **字号 `A` 与主预览同一套键位**：走同一份 `useHeaderActionShortcuts`，这一层只挂 `onToggleFont`
  （筛选 / 复制 / 刷新这些能力这一层没有，hook 按回调可选挂接，不传的按键不动作），tooltip 末尾同样标 `（A）`；
  翻篇与 `F` 全屏归外壳 `FreeModal`，不在这个 hook 里；面板开着时 `closeOnEscape` 关掉，Esc 只收面板、不关这一层预览；
- **链接那一层的切换范围由 header 的「区块预览切换范围」设置决定**（`listAnchorBlockPeers(blocks, anchor, scope)`）：
  `all` 是上面那条全文列表；`section` 只留同一处目录里的链接，计数随之变成这一处的条数
  （例：讲解两处 → `1 / 2`、`2 / 2`）。切块仍是跳 `index`，只是「下一个」的 index 从这一组里取，
  所以 `section` 口径下会跨小节跳（讲解里的两个链接分别指向两轮不同的 h1）；组里只有一块时两侧按钮都置灰；
- **正文不重复本节标题**：区块从标题的下一行开始截取，标题只出现在 header；块内目录因此也只列
  下属标题（跳到 h2 时目录里是它的 h3…），目录高亮与点目录定位都按这份短了一层的正文算；
- 字号 / 全屏与主预览**共用同一份记住的值**，换块不重置；字号弹层换块后按归属算作收起
  （记录「这一块」的派生状态，不在 effect 里 `setState`）；
- 换块时正文回到顶部（`useDocumentScrollReset`），目录高亮按**这一块**的标题重算；
- 块内还有同文档链接时**只在这一块内部跳**，不再往下开第三层；
- 排版样式直接复用主预览的样式模块（`../index.scss` 的 `.workspace` / `.pane` / `.prose`），
  这一层自己不再带样式文件——同一套 `.prose` 维护两份迟早会漂；
- 尺寸档走外壳的 `contentStyle`（只覆盖高度 / 宽度，边框圆角底色仍归 `FreeModal`）：
  常规态框体更矮（`74dvh` / 上限 `82dvh`），**全屏时宽高各占 95%**——它是叠在主预览上面的一层，
  全屏时也不该和主预览长得一模一样，否则分不清自己在看哪一层。宽度要连 `flex` 一起写
  （`0 0 95vw`），只改 `width` 会被 Mantine 全屏的 flex-basis 压回满宽；
- **嵌套浮层的边界**：子预览开着时主预览 `closeOnEscape={false}`、`trapFocus={false}`，
  让 Esc 与 Tab 先落在子预览上（子预览自己响应 Esc 关闭）；主预览的翻篇快捷键同时停用——
  那时的 `]` / → 归子预览用来切块，不该把底下那一篇偷偷换掉。两层都用默认 `zIndex`，**不要给子预览设 400**：
  会把门户里 `Popover`（300）压住。

### 导航

header 里、**标题左侧**的上一个 / 下一个图标按钮，配合快捷键翻篇：

| 按键 | 动作 |
| --- | --- |
| `]` / `】` | 下一篇 |
| `[` / `【` | 上一篇 |
| `→` | 下一篇（旧习惯，保留） |
| `←` | 上一篇（旧习惯，保留） |

`【` `】` 是中文输入法下同一个物理键打出的全角方括号，两种形态都认。快捷键只在**预览态**
（含全屏）生效，且**正在输入时不抢字符**——筛选面板里打字时字符属于输入框（`@/utils/typing-target`）；
到头的那一侧 `null`，按键不动作。

到头那一侧的按钮是 `disabled`，但**不保留 Mantine 给禁用态抹的灰底**（`.stepButton:disabled` 把
底色与描边都清掉，只留 `opacity: 0.4`）：这一排图标按钮平时是透明的，只有它突然多一块
`--mantine-color-disabled` 的底色，看起来像「上一个被选中」。子区域预览的那两个切换按钮同一份口径。

**按键只执行动作，不碰焦点**：以前按键会把焦点挪到对应那一侧的按钮（让焦点环指示方向），
现在不这么做——键盘触发完动作、按钮上再留一圈主色焦点环，看起来像「刚才点的是这个按钮」，
还会改掉之后的 Tab 起点。视觉上的一致性交给「全站不画焦点环」：主题里
`focusRing: 'never'`（`src/main.tsx`，注释里写了取舍——输入框的聚焦提示走
`--input-bd-focus` 换边框色，不受影响）。子区域预览的切块快捷键同一条口径。

### header 操作快捷键

预览态按字母键触发 header 上对应的按钮（`a` / `s` / `c` / `r`，大小写都认；`f` 全屏与 `[` `]`
← → 翻篇在 `FreeModal` 里统一处理，不在这一组）：

| 按键 | 动作 |
| --- | --- |
| `a` | 开合字号面板（已开字号则收起） |
| `s` | 开合筛选面板（已开筛选则收起） |
| `c` | 复制相对路径 |
| `r` | 刷新正文 |

口径与翻篇 / 删除快捷键一致：带 ⌘ / Ctrl / Alt 的组合键放行；正在输入（筛选面板输入框、
可编辑区）时不抢字符；子区域预览、删除确认层开着时停用；动作没有对应能力（没传路径 / 刷新 /
筛选槽）时按键不动作。复制、刷新的成功 / 失败都走固定通知 id，连按不叠一屏；刷新成功给一条
短提示「已刷新」，失败提示留着等处理。

带快捷键的按钮，tooltip 文案末尾都标注对应键位（如「筛选正文（S）」「上一篇（[ / ←）」
「删除这篇文档（Delete）」）；子区域预览同理：字号标 `（A）`，全屏的 `（F）` 由外壳统一标注。

### 复制相对路径

header 右侧的复制图标按钮（排在刷新之前、只在预览态出现），**调用方传 `relativePath` 才出现**：

- 点一下把这串相对路径（相对文档所在记录仓库根目录，如 `learning-record-notes/x.md`）写进剪贴板，
  图标 1.5 秒内变成对勾；尺寸与同排图标同档（15px / sm），**编辑态与草稿预览不显示**；
- 路径由调用方拼，组件不假设文件落在哪里（按钮本体是公共的 `src/components/buttons/CopyIconButton`）。

### 删除

header 文档操作组**最后一个**图标（垃圾桶，颜色与同排图标一致：常态弱色、hover 主色，
不做红色实底或常态描红，红色只出现在确认层的删除按钮上），
**调用方传 `remove` 才出现**，加载中没有正文可删所以也不出现；编辑态与草稿预览随整组收掉。

- **点一下不开删**：先弹二次确认层（`DeleteConfirm`，叠在主预览上面的一层 `Modal`，
  宽 420、框体底色取 `--app-surface`）；正文说明由调用方给（`remove.description`），组件不写死
  「删了什么、能不能撤回」——组件的另一处调用方可能根本不是删文件；
- **确认层按「先读、再选、做」排**：标题区（「删除这个文档？」+ 被删文档的 `title` 原文）→ 说明块 →
  可选的勾选项（`remove.choices`）→ 一条细线 → 靠右的两个按钮。勾选项不进按钮行：
  那一行只留两个出口，选择属于内容区。
  **不挂危险语气图标、也不在按钮旁写 `Esc` 键帽提示**——一段说明 + 两个出口就够了。
  **文件名不塞进标题**：路径一长会把「？」挤到下一行，所以标题只说「删这个文档」，
  路径另起一行 monospace 弱色（`overflow-wrap: anywhere`，长路径按任意位置折行）；
- 说明块自带一层软底与细边（`--app-surface-subtle` + `--app-line`），读起来是一段引注；
  按钮行上面一条细线（`--app-line`）把「读」和「做」分开；
- 确认层两个出口：`取消`（只收这一层）与 `删除`（危险实底主按钮，调用 `remove.confirm()`，
  返回 Promise 时按钮显示 loading，期间 `取消`、Esc、点遮罩都不可用，
  避免删到一半又点走）。删除按钮**只改 `--button-bg` / `--button-hover` / `--button-color`
  三个组件库变量**（取 `--app-status-danger-fill(-hover)`，暗色另有一档深底保证白字可读），
  不覆写 `background`：hover、loading、disabled 仍由组件库自己算；Mantine 自带那档红偏亮，
  与项目的墨绿 / 陶红不搭，所以换成项目令牌；
- **快捷键 `Delete` / `Backspace`**（`hooks/useRemoveShortcut`）：预览态按一下直接打开这一层确认，
  与点垃圾桶**走同一条路**（都经过 `removal.request`），**不会一按就删**。
  两个键都认是因为 macOS 键盘上印着「delete」的那颗发出来的是 `Backspace`。
  只在「真的能删」时响应：调用方传了 `remove`、非编辑态 / 草稿预览、`loading` 为假，
  且 header 弹层、子区域预览、确认层都没开着；带 ⌘ / Ctrl / Alt 的组合键放行，正在输入时
  （`@/utils/typing-target`）不抢字符；
- **删除失败的归属**：`confirm` 抛错由 `useRemoveRequest` 弹一条红色通知，确认层收起、
  正文与弹窗留在原处——不能先关掉弹窗再说「其实没删」；
- **勾选项（`remove.choices`）**：说明块下方**紧凑一行**（`Checkbox` 取 `size="xs"`，每项自带 4px / 8px
  内边距当可点区域，不做负边距；挤得下就并排、挤不下折行）。
  每项只显示 `label` 一个词（如「Markdown」「Record」），细节挂在 `hint` 上——鼠标 hover 出 tooltip，
  不给正文多占一行小字。**整项都是 hover / 可点区域**：浅底（`--app-surface-hover`）+ 圆角 + 小手
  （`cursor: pointer`，连子元素的默认箭头也盖掉），`focus-within` 也给同一层底；
  删除中（input 被禁用）不给底、`cursor: not-allowed`。
  方框与文字的纵向对齐靠 root 的 `align-items: center` + label 的 `padding-top: 0` 兜住——
  Mantine 默认顶部对齐，label 比 14px 方框高时会歪一截。`defaultChecked` 决定每次打开确认层时的
  初始勾选（默认都不勾）。**说明块可以传函数**：`description(checkedKeys)` 按当前勾选现算，所以勾选一变
  「这次删什么、留什么」在按下删除之前就跟着变。**一项都没勾时删除按钮 `disabled`**——没有可删的
  内容。勾选集合由 `useRemoveRequest` 持有，每次打开都回到各项的 `defaultChecked`、不跨次记住，
  确认时作为 `confirm(checkedKeys)` 的参数交给调用方，组件不解释 key 意味着什么
  （「Markdown / Record 各留哪一边」这类语义归调用方）。没有传 `choices` 时这一块整块不出；
- **删除成功不归组件管**：调用方在 `confirm` 里关弹窗、把这一篇从列表里摘掉、提示提交 / 推送状态；
- **嵌套浮层边界**：确认层开着时主预览 `closeOnEscape={false}`、`trapFocus={false}`，
  Esc 与 Tab 先落在确认层上（与子区域预览同一套口径）。

### 标题导航（左侧目录列）

弹窗**左侧固定的一列**文档内 h1–h4 目录 sidebar，按层级折成树：

- 每深一层向右缩进一段、左侧多一条极淡的引导线（顶层不画线），层级靠线 + 字号 / 颜色区分；
- 字号基准按全屏写（行 13.6px、一级 14px、其余 12.9px），**非全屏由目录列统一减 2px**
  （改一个 `--outline-shrink` 变量即可，Item 里的字号都是 `calc(基准 - var(--outline-shrink))`）；
- 有子标题的节点在标题右侧带折叠图标（右对齐）；
  **常规只展开第一个节点及其第一个子级，全屏预览时默认全部展开**；
- 点标题会跳转并顺带展开，收起只能点图标；**滚动正文时目录跟随高亮当前所在的小节，并把它的祖先链
  补展开**、高亮行滚出目录可视区时自动滚回来（手动收起同一分支会保留，直到滚到别的小节）；
- 编辑态没有正文可测量，激活项取「最近一次跳转到的标题」（不跟编辑器滚动联动），进入 / 退出编辑时清空；
- 目录占独立一列（常规 184px、全屏 300px）、高度由布局自然拉伸、只在目录列内滚动（不再测量正文高度
  封顶），滚动条贴右边缘、做细；窄屏（≤720px）目录挪到正文上方一条横带、最多占三成高度。
- **列宽可拖、拖到接近左边就收起**（`OutlineNav/hooks/useOutlineWidth`）：拖动条压在右侧分界线上，
  hover / 聚焦才浮出一条短竖线；展开区间 140–480px 且不超过工作区的 45%，松手宽度不到 72px 就认定收起；
  收起后列宽归零、内容整块隐藏，只剩那条 1px 分界线与正文左内边距里的一个箭头窄轨，**点窄轨（或往右拖）
  还原上次宽度**；`←` / `→` 按 16px 微调、`Enter` / `空格` 收起展开（拖动条是 `role="separator"`）；
  宽度与收起状态存在 `localStorage`（键见 `constants.ts` 的 `OUTLINE_WIDTH_STORAGE_KEY`），
  拖动过程只改本地状态、松手才落存储；窄屏横带里拖动条整条隐藏、收起偏好也不生效。
- **目录列与正文同一张纸**（底色取弹窗下发的 `--preview-paper`），只靠右侧一条细线分列；不用纯白
  把它抬成另一块面板——否则浅色主题下这一列会比正文明显更亮。条目底色按纸面 → hover → 选中递进：
  hover / 聚焦用主色最浅一档 `accent-soft`（不要白底，白滑块在纸面上太扎），当前小节用重一档的
  `accent-soft-strong`（目录列已是纸色，最浅那档叠上去几乎看不出选中）。

### hook 分工（实现约束）

正文里的交互与 header 的快捷键各自收成一个 hook，`index.tsx` 只负责把它们排到 header 与浮层上
（单个文件 300 行的上限由 `pnpm lint` 兜住，别再往里塞）：

| hook | 拿着什么 |
| --- | --- |
| `useDocumentInteractions` | 锚点区块 + 折叠块的解析结果、四份阅读偏好（链接 2 / 折叠块 2）、两层子预览、正文点击路由（先折叠块、再链接）、`close` 与 `subPreviewOpen` |
| `usePreviewHeaderActions` | 字号面板 / 筛选面板开合、命中导航、复制路径通知，并接线 `useHeaderActionShortcuts` |

### 正文渲染性能

正文渲染结果必须用 `useMemo` 包住（只依赖 `renderedMarkdown`）：`react-markdown` 每次渲染都会重新解析
整篇，正文节点挂载、刷新、编辑态切换这类内部状态变化时重解析一次就是几十毫秒的「点开卡一下」。

### 全屏预览

header 右侧的图标按钮（排在刷新之后、编辑操作之前；编辑态不显示），点了把整个框体铺满视口
（去外边距、描边与圆角），目录默认全展开且列加宽，正文行宽收在一栏并居中，只放大可读高度。
注意这条只属于**主预览**：子区域预览的全屏另有口径（宽高各 95%，见下一节）。

- **正文整体再放大 2px**（正文、各级标题、表格、折叠块标题同档）：各档字号都写成
  `calc(基准 + var(--prose-grow) + var(--prose-extra))`，`.prose` 里 `--prose-grow` 为 `0px`，
  全屏的 `.proseFullscreen` 给它 `2px`——要改全屏字号只动这一个变量，别逐条改 `font-size`；
  `--prose-extra` 是 header 字号按钮调出来的用户偏移（见下一节「正文字号」），两者相加、互不覆盖；
- **header 与左侧目录不跟着放大**：目录自己有 `--outline-shrink`（全屏本来就比常规大 2px），
  header 固定原尺寸，放大只发生在正文区；
- **Esc 不退出全屏，永远关掉弹窗**（全屏只是「框体铺满视口」这一层外观，不是另一种模式；
  同一个键在两种状态下干不同的事，用户只会记住那一次「按了没关掉」）。要回常规大小只有一条路：
  再点一次这个图标；关掉弹窗后再打开仍是全屏（见下一条）；
- **全屏是记住的偏好**（`localStorage`，键见 `constants.ts` 的 `FULLSCREEN_STORAGE_KEY`）：换篇、关掉重开、
  刷新页面后再打开都还是上次的样子，关闭弹窗不会把它重置成常规大小。

### 正文字号

header 文档操作组里的字号图标（排在筛选之后、刷新之前；编辑态随整组收掉），点一下在图标下方就近弹出
面板（`ProseFontControl`：`bottom-end`、宽 208、带箭头；与 `FilterButton` 同一套按钮外观）：

- 面板里「减 / 加」各一档（步长 1px、范围 −2～+6px，到边界按钮置灰），「恢复默认」把偏移清零；
- 调的是**用户偏移**（`--prose-extra`，内联 CSS 变量），叠在常规 / 全屏各自的默认字号上：
  退出全屏不会把调过的结果冲掉，全屏那 2px 照旧；
- 偏移**跨篇、跨会话记住**（`localStorage`，键见 `constants.ts` 的 `PROSE_FONT_STORAGE_KEY`）；
  手工改坏的存储值由 `useProseFontScale` 的 `clampOffset` 夹回范围，不会渲染出离谱字号；
- 不是默认值时图标常态换主色，与「筛选生效」同一个表达；
- 弹层与筛选 / 文档内交互弹层**互斥**：header 同一时刻只开一块（弹窗里的 `panel` 状态，取值见 `PreviewPanel`），
  换篇 / 刷新 / 进编辑 / 关弹窗一起收起；面板开着时 Esc 只收面板，弹窗不跟着关。

### 换篇（上一篇 / 下一篇）

**不重挂弹窗、不退出全屏**——全屏是「怎么看」，不属于某一篇。属于「这一篇」的复位由组件自己做：

- 保存状态提示带着所属标题存（标题对不上就当没有提示，`SaveHintState`）；
- 正文滚回顶部（`hooks/useDocumentScrollReset`）。

调用方**不要**用 `key={文件名}` 重挂弹窗来清换篇状态，那会把全屏一起重置，表现为切一篇就掉出全屏。

### header 与保存状态

**弹窗没有 footer**：编辑 / 预览 / 保存 / 放弃改动与状态提示全部收进 header 右侧，只留图标 + tooltip
（`aria-label` 与 tooltip 同一句人话）：

- **header 走紧凑版**：上下内边距只有 6px，header 高度由行内最高的那个按钮（关闭按钮 md = 28px）决定，
  实际约 41px——要更矮就换更小的按钮，别再往上加固定 `height`；
- **必须覆盖掉 Mantine 的 `min-height`**：它给 modal header 垫了 `min-height: calc(3.75rem * scale)`（60px），
  不写 `min-height: 0` 时内边距怎么压 header 都还是 60px。所以这条规则写成 `.content .header` 双类名，
  不依赖 CSS 的加载顺序；单类名会被 Mantine 那套 padding / min-height 顶回来；
- 未编辑时是「编辑（铅笔）」；进入编辑态换成「退出编辑（返回箭头）/ 预览草稿（眼睛）/ 保存（对勾，主色）」；
- 右侧图标分成两组：**文档操作组**（复制路径 / 筛选 / 正文字号 / 文档内交互方式 / 刷新）在
  `headerActions`，**全屏**由 `FreeModal` 自己给（`fullscreen` 插槽），**删除**排在它之后的 `headerTail`；
  **编辑流程**在 `headerSecondary`，与前面的操作组之间**不画**分割线；
- **编辑态与草稿预览只保留编辑流程这一组**（退出、预览、保存），文档操作组整组不渲染——新增这类按钮
  放进 `DocumentActions`（`headerActions` 插槽）即可，`documentActionsVisible` 只在弹窗里判一次；
- 唯一的竖分割线画在**关闭按钮 X 之前**（操作区与关闭的分界，由 `FreeModal` 统一给），
  「给关闭按钮让出的间距」也跟着它一起出现；编辑态没有关闭按钮，两者都不渲染；
- 保存成功在图标左侧显示「已保存・HH:MM」并在 3 秒内淡出（连续保存不会互相踩定时器）；
- 编辑态（含草稿预览）那排图标放大一档（18px 图标 / lg 按钮），非编辑态（只有铅笔）与刷新 / 全屏 / 关闭
  同档（15px / sm）；
- 保存失败显示红色错误文案，超长时省略、hover 弹完整内容。

### 编辑态不可关闭

**编辑态（含草稿预览）弹窗根本关不掉**：

- 关闭按钮不渲染；Esc 与点遮罩都只弹一条「编辑中不能关闭预览」的提示（固定 notification id，连按不会
  叠一屏；草稿预览态提示走「返回编辑」那条路）；
- 全屏按钮也收掉（全屏只会把块编辑器抻大）；
- 唯一出口是「返回箭头」：先退出编辑，关闭与全屏才回来。

### 草稿预览

编辑态点「预览」把正文换成草稿的渲染结果（编辑器只隐藏、不卸载，草稿 / 撤销栈 / 光标都留着），
header 的操作缩成「返回编辑」「保存」；点「返回编辑」回到编辑态接着改，点「保存」才落盘。
预览草稿期间跨文档的快捷键（`[` `]` 与 `←` `→`）仍禁用（避免草稿被换掉）。

### 编辑插槽

组件**不带默认编辑器**，具体编辑界面由调用方通过 `Editor` 传入；没有传 `Editor` 时点「编辑」只弹提示。
编辑器可选实现 `onHandleReady(handle | null)`：交上来一个 `revealHeading(index)` 就能让编辑态的标题目录
可用（编辑态正文不渲染，目录只能由编辑器自己定位）；不实现时编辑态点目录没有反应。
实现方式与各文档类别的编辑器见 `docs/markdown-editing.md`。

### 退出编辑保护

编辑中且有未保存改动时，点「返回箭头」先在 header 二次确认（提示「这份改动还没保存」+
「继续编辑（返回箭头）」/「放弃改动并退出编辑（红色垃圾桶）」），不会静默丢改动；确认放弃只是退出编辑态，
弹窗仍开着（这时才轮到关闭）；编辑态标题目录保持可点（由编辑器定位到对应块），不再是置灰的死列。

### 关闭、键盘可访问性与焦点管理

关闭入口、遮罩行为、焦点进出弹窗都按 Mantine `Modal` 的既有能力处理，自定义按钮一律带
`aria-label`（与 tooltip 同一句话）。

**初始焦点不落到 header 图标上**：focus trap 激活时默认聚焦弹窗内第一个可聚焦元素，翻篇按钮
disabled 时会落到第一个图标按钮上，把复制按钮那类 focus 型 tooltip 撞成常驻。弹窗内放一个
`FocusTrap.InitialFocus`（`data-autofocus` 隐藏节点）让 trap 先选中它；只有用户手动按
Tab 进入按钮序列时，才是真实键盘聚焦、tooltip 才该打开。

`Esc` 的语义**只有一个：关掉弹窗**，任何外观状态下都不变：

| 当时状态 | 按 Esc |
| --- | --- |
| 预览态（含全屏） | 关掉弹窗；全屏是记住的偏好，下次打开还是全屏 |
| header 弹层开着 | 只收弹层，弹窗留着（两层浮层不该被一下全关掉，`closeOnEscape` 由 `panel` 把关） |
| 删除确认层开着 | 只收确认层，弹窗留着（`closeOnEscape` 由 `remove` 的 `confirming` 把关；删除中 Esc 不动作） |
| 子区域预览开着（链接区块 / 折叠块任一层） | 只关那一层，主弹窗留着（`closeOnEscape` 由 `interactions.subPreviewOpen` 把关） |
| 编辑态 / 草稿预览 | 不关，只弹「编辑中不能关闭预览」的提示（`useCloseRequest`） |

**空格与 Esc 同一口径**（同样封装在 `FreeModal` 里）：非编辑态按空格即关窗，并挡掉浏览器
「空格 = 点击当前焦点按钮」的默认行为——否则焦点留在 header 图标上时按空格会莫名翻篇 / 切全屏。
