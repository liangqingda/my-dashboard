# Markdown 预览弹窗（`MarkdownPreviewModal`）

组件规格，跟代码放在一起（非全局性文档不进 `docs/`）。**什么时候必须用它（选型）**归
`docs/ui-components.md` 的「场景 → 用哪个」，本文件只讲它的行为契约与实现约束。

渲染栈固定为 `react-markdown` + `remark-gfm` + `rehype-raw`（需要 GFM 表格与 `<details>` 折叠块）；
新增 Markdown 能力时改这个组件，不要在别处另装渲染器。

职责边界：**调用方**决定「相邻文档是谁」「保存落到哪里」以及「这类文档怎么编辑」（编辑插槽见
`docs/markdown-editing.md`）；**导航与编辑态流程**由组件负责。

## props 契约

| prop | 类型 | 说明 |
| --- | --- | --- |
| `opened` | `boolean` | 是否打开 |
| `title` | `string` | 标题，通常传文件名 |
| `markdown` | `string` | Markdown 原文 |
| `loading` | `boolean`（可选） | 正文是否还在取。为 `true` 时正文区只显示居中加载指示、不渲染 Markdown，标题目录为空且不可点，刷新与编辑入口一并收起（没有正文可编辑，也不该把空串写成一篇空文档）。打开 / 翻篇 / 刷新过程中由调用方传 |
| `position` | `{ index: number; total: number }`（可选） | 展示「第几 / 共几」 |
| `relativePath` | `string`（可选） | 文档的相对路径（相对其记录仓库根目录）；提供后 header 出现复制图标按钮，不传则不显示。组件不拼路径，由调用方给 |
| `onClose` | `() => void` | 关闭 |
| `onPrevious` | `(() => void) \| null`（可选） | 上一篇；`null` 表示到头，按钮置灰 |
| `onNext` | `(() => void) \| null`（可选） | 下一篇；`null` 表示到头，按钮置灰 |
| `onRefresh` | `(() => Promise<void> \| void) \| null`（可选） | header 右侧操作组里的刷新按钮；调用方重取最新正文并回灌 `markdown`，返回 Promise 时按钮显示 loading，不传则不显示；编辑中不渲染（刷新会把草稿盖掉） |
| `onSave` | `(markdown: string) => Promise<{ notice?: string }>`（可选） | 提供后才出现「编辑」；落盘由调用方实现，抛错则显示为保存失败，返回的 `notice` 追加在「已保存」提示后 |
| `Editor` | `ComponentType<MarkdownEditorProps>`（可选） | 这一类文档的定制编辑器；不传则点「编辑」只给定制提示 |
| `filter` | `MarkdownPreviewFilter`（可选） | 预览态的内容筛选槽：传了才出现 header 的筛选图标按钮与就近弹层；筛什么、怎么持久化由调用方给。编辑态与保存始终用未筛选的原文 |

## 行为细节

### 文档排版

标题、表格、引用、代码块、`<details>` 折叠讲解等都由组件负责，调用方只给原文。

**`**加粗**` 不出字重**：正文里所有 `strong` 一律 `font-weight: 400`，颜色走 `--app-ink-strong`
（普通正文是 `--app-ink-soft`，标题是 `--app-ink`），强调靠墨色深浅区分而不是粗细。
`--app-ink-strong` **夹在正文与标题之间**：浅色下比标题浅一档、暗色下比标题暗一档，与标题始终留
1.3–1.5 倍亮度差；跟着标题往同一边推（浅色更黑 / 暗色更亮）会让加粗看起来像小标题，不要那样改。

### 筛选（内容由调用方定义）

header 文档操作组里的筛选图标按钮（排在复制路径之后、刷新之前；编辑态随整组收掉），
点一下在图标下方就近弹出面板（`src/components/FilterButton`：`bottom-end`、宽 272、带箭头；
英语页 header 的「筛选笔记」用的是同一个按钮组件）。
**弹窗不知道「错题」「习题」这类文档语义**：

- 面板内容、筛选口径、条件持久化都归调用方（`filter.render` / `filter.apply`），组件只管按钮与弹层开合；
- `apply` 只在**预览态**生效：编辑态（含草稿预览）不筛，编辑器与保存拿到的永远是未筛选的原文，
  避免把筛过的正文写回文件；标题目录按筛选后的正文重算，目录与屏上内容始终一致；
- `filter.active` 为真时图标换成主色、tooltip 改口；筛空时正文区显示「没有符合当前筛选条件的内容」，
  而不是一片空白；
- 换篇 / 刷新 / 进编辑 / 关弹窗都会收起面板；面板开着时 Esc 只收面板，不连弹窗一起关
  （`closeOnEscape` 由弹窗的 `panel` 状态把关）。与「正文字号」「同文档锚点链接」弹层互斥，同一时刻只开一块；

### 同文档锚点链接（`[文字](#锚点)`）

正文里的同文档链接（`href` 以 `#` 开头）有两种行为，由 header 文档操作组里的锚点图标按钮切换
（排在正文字号之后、刷新之前），**值是跨篇、跨会话记住的阅读偏好**（`localStorage`，
键见 `constants.ts` 的 `ANCHOR_LINK_STORAGE_KEY`；默认 `jump`，等于浏览器原行为）。
弹层里就是一个 `Select`（宽 220，`allowDeselect: false`），点开按钮时下拉**已经聚焦并展开**
（`autoFocus` + Mantine 默认的 `openOnFocus`），选一档就收起——少一次点击；
下拉**不进门户**（`comboboxProps={{ withinPortal: false }}`）：门户里的列表在 popover 眼里算「外面」，
点选项会先把弹层关掉、选择动作就丢了：

| 行为 | 点了同文档链接 |
| --- | --- |
| `jump`（默认） | 在当前正文里滚到锚点位置，目录高亮跟着走 |
| `modal` | 把锚点指向的那一节单独开窗（子区域预览），主弹窗留在原处 |

- **按钮只在文档里真有同文档锚点链接时出现**（`anchorBlocks.length > 0` 且非 `loading`）：
  没有可点的链接，这档设置也就无从验证；编辑态随整组文档操作一起收掉；
- 拦截方式是在 `<article>` 上挂 `onClick`、用 `event.target.closest('a')` 判定，**不用
  `components={{ a: … }}` 换掉 `a` 渲染器**——那会改掉 `react-markdown` 的组件对象，正文的 `useMemo`
  失去稳定性，长文档每渲染一次就重解析一遍。外链与相对路径一律放行（交给浏览器）；
  同文档锚点必须 `preventDefault()`，否则点一下会把地址栏改成 `#…`；
- 区块的切分口径（`utils/anchor-blocks.ts`，纯文本行扫描、跳代码围栏）：
  - 收集 h1–h4 标题行与 `<a id|name>` 定义行，以及 `](#x)` / `<a href="#x">` 指向的目标集合；
  - 锚点归到「它前面最后一个标题」这一节；一节到**下一个同级或更高级标题之前**为止，没有则到文末——
    所以跳到 h2 得到整节（含 h3），跳到 h3 只得到那一小节；
  - 每个标题只认第一个落在它这一节里的锚点；结果按标题顺序装配（不调用 `sort`）；
  - 第一个标题之前的锚点单独成一块（`level: 0`、无标题），标题显示锚点本身；
  - 取的是**未筛选**的正文：筛选只影响「读」，不该把某一节的内容筛没了；
- 弹窗模式下没认出区块（锚点没有对应标题）时**退回跳转**，不让点击白按一下；
- 锚点按钮的弹层与筛选 / 字号弹层互斥（同一个 `panel` 状态），换篇 / 刷新 / 进编辑 / 关弹窗一起收起。

### 子区域预览（锚点区块弹窗，`AnchorBlockModal`）

`modal` 行为下的那一层弹窗，组装在 `AnchorBlockPreview`（只管「当前第几块」与前后边界），
正文界面在 `AnchorBlockModal`：

| 位置 | 内容 |
| --- | --- |
| header 左侧 | 前一块 / 后一块图标按钮（`]` `[` 不参与）、计数（`第 3 / 4 块`）、当前区块标题（如 h2 文本） |
| header 右侧 | 只有正文字号、全屏、关闭（关闭按钮带 `aria-label="关闭区块预览"`） |
| 左侧 | 这一块自己的标题目录（复用 `OutlineNav`，标题少于两条时按它的规则不显示） |
| 正文 | 这一块的 Markdown 源文本（**不含本节标题行**，标题已经在 header 上），含它下属的更深层级 |

- **前后切换按正文顺序、不区分层级**：被链接指向的区块就是一个扁平列表，h2 与 h3 相邻时直接跳过去；
  到头的一侧按钮置灰；
- **正文不重复本节标题**：区块从标题的下一行开始截取，标题只出现在 header；块内目录因此也只列
  下属标题（跳到 h2 时目录里是它的 h3…），目录高亮与点目录定位都按这份短了一层的正文算；
- 字号 / 全屏与主预览**共用同一份记住的值**，换块不重置；字号弹层换块后按归属算作收起
  （记录「这一块」的派生状态，不在 effect 里 `setState`）；
- 换块时正文回到顶部（`useDocumentScrollReset`），目录高亮按**这一块**的标题重算；
- 块内还有同文档链接时**只在这一块内部跳**，不再往下开第三层；
- 排版样式直接复用主预览的样式模块（`../index.scss` 的 `.workspace` / `.pane` / `.prose`），
  自己的 `index.scss` 只写增量（框体更矮：`74dvh` / 上限 `82dvh`）——同一套 `.prose` 维护两份迟早会漂；
- **嵌套浮层的边界**：子预览开着时主预览 `closeOnEscape={false}`、`trapFocus={false}`，
  让 Esc 与 Tab 先落在子预览上（子预览自己响应 Esc 关闭）；主预览的翻篇快捷键同时停用——
  那时的 `]` / → 不该把底下那一篇偷偷换掉。两层都用默认 `zIndex`，**不要给子预览设 400**：
  会把门户里 `Popover`（300）压住。

### 导航

header 里、**标题左侧**的上一个 / 下一个图标按钮，配合快捷键翻篇：

| 按键 | 动作 |
| --- | --- |
| `]` / `】` | 下一篇 |
| `[` / `【` | 上一篇 |
| `→` | 下一篇（旧习惯，保留） |
| `←` | 上一篇（旧习惯，保留） |

`【` `】` 是中文输入法下同一个物理键打出的全角方括号，两种形态都认。快捷键只在**预览态**
（含全屏）生效，且**正在输入时不抢字符**——筛选面板里打字时字符属于输入框（`@/utils/typing-target`）；
到头的那一侧 `null`，按键不动作。

**焦点跟着方向走**：按键翻篇时先把焦点挪到那一侧的按钮（`]` → 下一篇、`[` → 上一篇），
那圈 `:focus-visible` 焦点环就落在「这次往哪边走」的箭头上。这是必需的——弹窗打开时 Mantine 的
焦点陷阱会把焦点放在弹窗里第一个可聚焦元素，也就是「上一篇」按钮，之后按任意键都会让左边那圈环
显形，看起来像「往右翻却亮着左边」。鼠标点按钮本身就会自然聚焦，不走这一层。

### 复制相对路径

header 右侧的复制图标按钮（排在刷新之前、只在预览态出现），**调用方传 `relativePath` 才出现**：

- 点一下把这串相对路径（相对文档所在记录仓库根目录，如 `learning-record-notes/x.md`）写进剪贴板，
  图标 1.5 秒内变成对勾；尺寸与同排图标同档（15px / sm），**编辑态与草稿预览不显示**；
- 路径由调用方拼，组件不假设文件落在哪里（按钮本体是公共的 `src/components/CopyIconButton`）。

### 标题导航（左侧目录列）

弹窗**左侧固定的一列**文档内 h1–h4 目录 sidebar，按层级折成树：

- 每深一层向右缩进一段、左侧多一条极淡的引导线（顶层不画线），层级靠线 + 字号 / 颜色区分；
- 字号基准按全屏写（行 13.6px、一级 14px、其余 12.9px），**非全屏由目录列统一减 2px**
  （改一个 `--outline-shrink` 变量即可，Item 里的字号都是 `calc(基准 - var(--outline-shrink))`）；
- 有子标题的节点在标题右侧带折叠图标（右对齐）；
  **常规只展开第一个节点及其第一个子级，全屏预览时默认全部展开**；
- 点标题会跳转并顺带展开，收起只能点图标；**滚动正文时目录跟随高亮当前所在的小节，并把它的祖先链
  补展开**、高亮行滚出目录可视区时自动滚回来（手动收起同一分支会保留，直到滚到别的小节）；
- 编辑态没有正文可测量，激活项取「最近一次跳转到的标题」（不跟编辑器滚动联动），进入 / 退出编辑时清空；
- 目录占独立一列（常规 184px、全屏 300px）、高度由布局自然拉伸、只在目录列内滚动（不再测量正文高度
  封顶），滚动条贴右边缘、做细；窄屏（≤720px）目录挪到正文上方一条横带、最多占三成高度。
- **列宽可拖、拖到接近左边就收起**（`OutlineNav/hooks/useOutlineWidth`）：拖动条压在右侧分界线上，
  hover / 聚焦才浮出一条短竖线；展开区间 140–480px 且不超过工作区的 45%，松手宽度不到 72px 就认定收起；
  收起后列宽归零、内容整块隐藏，只剩那条 1px 分界线与正文左内边距里的一个箭头窄轨，**点窄轨（或往右拖）
  还原上次宽度**；`←` / `→` 按 16px 微调、`Enter` / `空格` 收起展开（拖动条是 `role="separator"`）；
  宽度与收起状态存在 `localStorage`（键见 `constants.ts` 的 `OUTLINE_WIDTH_STORAGE_KEY`），
  拖动过程只改本地状态、松手才落存储；窄屏横带里拖动条整条隐藏、收起偏好也不生效。
- **目录列与正文同一张纸**（底色取弹窗下发的 `--preview-paper`），只靠右侧一条细线分列；不用纯白
  把它抬成另一块面板——否则浅色主题下这一列会比正文明显更亮。条目底色按纸面 → hover → 选中递进：
  hover / 聚焦用主色最浅一档 `accent-soft`（不要白底，白滑块在纸面上太扎），当前小节用重一档的
  `accent-soft-strong`（目录列已是纸色，最浅那档叠上去几乎看不出选中）。

### 正文渲染性能

正文渲染结果必须用 `useMemo` 包住（只依赖 `renderedMarkdown`）：`react-markdown` 每次渲染都会重新解析
整篇，正文节点挂载、刷新、编辑态切换这类内部状态变化时重解析一次就是几十毫秒的「点开卡一下」。

### 全屏预览

header 右侧的图标按钮（排在刷新之后、编辑操作之前；编辑态不显示），点了把框体放大成
**高度铺满视口、宽度 90vw**（左右各留一道缝，能看出是「在页面里放大」而不是换了一屏；去外边距、
描边与圆角），目录默认全展开且列加宽，正文行宽收在一栏并居中，只放大可读高度。

宽度这条写在 `.content.contentFullscreen` 的 `flex` 与 `width` 两处：全屏时 Mantine 给的是
`--modal-content-flex: 0 0 100%`，只改 `width` 会被 flex-basis 压回满宽。

- **正文整体再放大 2px**（正文、各级标题、表格、折叠块标题同档）：各档字号都写成
  `calc(基准 + var(--prose-grow) + var(--prose-extra))`，`.prose` 里 `--prose-grow` 为 `0px`，
  全屏的 `.proseFullscreen` 给它 `2px`——要改全屏字号只动这一个变量，别逐条改 `font-size`；
  `--prose-extra` 是 header 字号按钮调出来的用户偏移（见下一节「正文字号」），两者相加、互不覆盖；
- **header 与左侧目录不跟着放大**：目录自己有 `--outline-shrink`（全屏本来就比常规大 2px），
  header 固定原尺寸，放大只发生在正文区；
- **Esc 不退出全屏，永远关掉弹窗**（全屏只是「框体铺满视口」这一层外观，不是另一种模式；
  同一个键在两种状态下干不同的事，用户只会记住那一次「按了没关掉」）。要回常规大小只有一条路：
  再点一次这个图标；关掉弹窗后再打开仍是全屏（见下一条）；
- **全屏是记住的偏好**（`localStorage`，键见 `constants.ts` 的 `FULLSCREEN_STORAGE_KEY`）：换篇、关掉重开、
  刷新页面后再打开都还是上次的样子，关闭弹窗不会把它重置成常规大小。

### 正文字号

header 文档操作组里的字号图标（排在筛选之后、刷新之前；编辑态随整组收掉），点一下在图标下方就近弹出
面板（`ProseFontControl`：`bottom-end`、宽 208、带箭头；与 `FilterButton` 同一套按钮外观）：

- 面板里「减 / 加」各一档（步长 1px、范围 −2～+6px，到边界按钮置灰），「恢复默认」把偏移清零；
- 调的是**用户偏移**（`--prose-extra`，内联 CSS 变量），叠在常规 / 全屏各自的默认字号上：
  退出全屏不会把调过的结果冲掉，全屏那 2px 照旧；
- 偏移**跨篇、跨会话记住**（`localStorage`，键见 `constants.ts` 的 `PROSE_FONT_STORAGE_KEY`）；
  手工改坏的存储值由 `useProseFontScale` 的 `clampOffset` 夹回范围，不会渲染出离谱字号；
- 不是默认值时图标常态换主色，与「筛选生效」同一个表达；
- 弹层与筛选 / 锚点弹层**互斥**：header 同一时刻只开一块（弹窗里的 `panel` 状态，取值见 `PreviewPanel`），
  换篇 / 刷新 / 进编辑 / 关弹窗一起收起；面板开着时 Esc 只收面板，弹窗不跟着关。

### 换篇（上一篇 / 下一篇）

**不重挂弹窗、不退出全屏**——全屏是「怎么看」，不属于某一篇。属于「这一篇」的复位由组件自己做：

- 保存状态提示带着所属标题存（标题对不上就当没有提示，`SaveHintState`）；
- 正文滚回顶部（`hooks/useDocumentScrollReset`）。

调用方**不要**用 `key={文件名}` 重挂弹窗来清换篇状态，那会把全屏一起重置，表现为切一篇就掉出全屏。

### header 与保存状态

**弹窗没有 footer**：编辑 / 预览 / 保存 / 放弃改动与状态提示全部收进 header 右侧，只留图标 + tooltip
（`aria-label` 与 tooltip 同一句人话）：

- **header 走紧凑版**：上下内边距只有 6px，header 高度由行内最高的那个按钮（关闭按钮 md = 28px）决定，
  实际约 41px——要更矮就换更小的按钮，别再往上加固定 `height`；
- **必须覆盖掉 Mantine 的 `min-height`**：它给 modal header 垫了 `min-height: calc(3.75rem * scale)`（60px），
  不写 `min-height: 0` 时内边距怎么压 header 都还是 60px。所以这条规则写成 `.content .header` 双类名，
  不依赖 CSS 的加载顺序；单类名会被 Mantine 那套 padding / min-height 顶回来；
- 未编辑时是「编辑（铅笔）」；进入编辑态换成「退出编辑（返回箭头）/ 预览草稿（眼睛）/ 保存（对勾，主色）」；
- 右侧图标分成两组：**文档操作组**（复制路径 / 筛选 / 正文字号 / 同文档锚点链接 / 刷新 / 全屏）在前，**编辑流程**在后，
  两组之间一条竖分割线；
- **编辑态与草稿预览只保留编辑流程这一组**（退出、预览、保存），文档操作组整组不渲染——新增这类按钮
  放进 `TitleBar` 的 `documentActions` 组即可，不必每个再判一次编辑态；
- 竖分割线与「给关闭按钮让出的间距」只在文档操作组出现时才有（编辑态没有关闭按钮，也不留这段）；
- 保存成功在图标左侧显示「已保存・HH:MM」并在 3 秒内淡出（连续保存不会互相踩定时器）；
- 编辑态（含草稿预览）那排图标放大一档（18px 图标 / lg 按钮），非编辑态（只有铅笔）与刷新 / 全屏 / 关闭
  同档（15px / sm）；
- 保存失败显示红色错误文案，超长时省略、hover 弹完整内容。

### 编辑态不可关闭

**编辑态（含草稿预览）弹窗根本关不掉**：

- 关闭按钮不渲染；Esc 与点遮罩都只弹一条「编辑中不能关闭预览」的提示（固定 notification id，连按不会
  叠一屏；草稿预览态提示走「返回编辑」那条路）；
- 全屏按钮也收掉（全屏只会把块编辑器抻大）；
- 唯一出口是「返回箭头」：先退出编辑，关闭与全屏才回来。

### 草稿预览

编辑态点「预览」把正文换成草稿的渲染结果（编辑器只隐藏、不卸载，草稿 / 撤销栈 / 光标都留着），
header 的操作缩成「返回编辑」「保存」；点「返回编辑」回到编辑态接着改，点「保存」才落盘。
预览草稿期间跨文档的快捷键（`[` `]` 与 `←` `→`）仍禁用（避免草稿被换掉）。

### 编辑插槽

组件**不带默认编辑器**，具体编辑界面由调用方通过 `Editor` 传入；没有传 `Editor` 时点「编辑」只弹提示。
编辑器可选实现 `onHandleReady(handle | null)`：交上来一个 `revealHeading(index)` 就能让编辑态的标题目录
可用（编辑态正文不渲染，目录只能由编辑器自己定位）；不实现时编辑态点目录没有反应。
实现方式与各文档类别的编辑器见 `docs/markdown-editing.md`。

### 退出编辑保护

编辑中且有未保存改动时，点「返回箭头」先在 header 二次确认（提示「这份改动还没保存」+
「继续编辑（返回箭头）」/「放弃改动并退出编辑（红色垃圾桶）」），不会静默丢改动；确认放弃只是退出编辑态，
弹窗仍开着（这时才轮到关闭）；编辑态标题目录保持可点（由编辑器定位到对应块），不再是置灰的死列。

### 关闭、键盘可访问性与焦点管理

关闭入口、遮罩行为、焦点进出弹窗都按 Mantine `Modal` 的既有能力处理，自定义按钮一律带
`aria-label`（与 tooltip 同一句话）。

`Esc` 的语义**只有一个：关掉弹窗**，任何外观状态下都不变：

| 当时状态 | 按 Esc |
| --- | --- |
| 预览态（含全屏） | 关掉弹窗；全屏是记住的偏好，下次打开还是全屏 |
| header 弹层开着 | 只收弹层，弹窗留着（两层浮层不该被一下全关掉，`closeOnEscape` 由 `panel` 把关） |
| 子区域预览开着 | 只关子预览，主弹窗留着（`closeOnEscape` 由 `anchorBlock.index` 把关） |
| 编辑态 / 草稿预览 | 不关，只弹「编辑中不能关闭预览」的提示（`useCloseRequest`） |
